# 医学多智能体系统失败归因 —— 标注协议

> 本协议供临床专家与标注团队使用。目标:对每条**已失败**的医学 MAS 轨迹,
> 标注(1)责任归因,(2)故障类型,(3)发现该错误所依赖的线索类型,(4)责任结构。
> 这四项分别支撑论文的"二元故障本体"、"结构签名 2×3 表"和"多重责任"分析。

---

## 0. 一条铁律(务必先读)

标注每个错误时,**两个判断必须分开、独立进行,不要互相参考**:

1. **归因判断**(第 3 部分):这个 agent *该不该* 这么做?(是否违反协作规范)
2. **线索判断**(第 4 部分):你是 *靠什么* 发现它错的?(内部矛盾 / 下游后果 / 需查外部知识)

这两个问题**逻辑上独立**。一个 agent 可能"违反了规范(该判它错)"但你"靠下游后果才发现";
也可能"没违反任何规范"却"恰好和别人的正确输出矛盾"。**先答完归因判断,再答线索判断,
中途不要回头改。** 这是本协议方法论的命脉——只有两个判断独立,交叉统计才有意义。

---

## 1. 标注单元

- 单元 = 一条**失败**轨迹(系统最终答案错误)。
- 每条轨迹可以标注**多个**问题步骤(真实失败常是多故障)。
- 每条轨迹由 **≥2 位专家独立标注**;约 20% 的轨迹由 ≥3 位标注(用于信度分析)。

**开始前,系统会显示(无需你判断,仅供参考)**:病例类型、参与的 agent 及其角色、
完整对话轨迹(逐步)、系统最终答案 vs 正确答案。

---

## 2. 第一层:定位错误步骤

通读轨迹,标出每一个你认为"出问题"的步骤:

| 字段 | 怎么填 |
|---|---|
| 步骤号 | 出问题的步骤编号 |
| 执行 agent | 该步骤的执行者(系统已给出) |
| 是否最早 | 这是否是本轨迹**最早**出问题的地方?(允许"并列最早") |

> 一条轨迹里"最早"原则上只标一个;若你认为有两处并列最早,可都标——这本身是有价值的信号。

---

## 3. 第二层:归因判断(该不该这么做)

**对每一个标出的错误步骤**,回答这一个核心问题:

> ### Q-归因
> **在这个 agent 的角色、它拿到的信息、它所处的协作阶段下,一个称职的 agent
> 本来是否应该避免这样做?换句话说 —— 它是否违反了某条它本应遵守的协作规范?**

三选一:

- **【A】违反了规范** —— 它做了不该做的,或没做该做的。
  → 接着标:**违反了哪条?**(从下方 MAST-14 规范清单选一条最贴切的 `fm_type`)

- **【B】没违反规范,但结果仍错** —— 它忠实履行了角色、走完了流程、尽到了义务,
  但它输出的**内容**本身是错的。
  → 接着标:**属于哪种模型固有错误?**
    - 事实幻觉(编造或记错客观临床事实)
    - 医学知识误用(用了过时/错误但"看似合理"的医学知识)
    - 感知缺陷(误读影像等模态信息;纯文本病例可忽略此项)
    - **其他(请用一句话描述)** ← 若你遇到上述都不贴切的情况,**务必在此描述**,
      这可能是一种尚未被记录的新故障类型,对研究极其重要

- **【?】不确定** —— 无法判断该不该这么做。(这个选项本身是有用的数据,不要回避)

### MAST-14 规范清单(A 类选项)

*每一条 FM 本质是"违反了某条协作契约"。选最贴切的那一条。*

**系统设计类**
- FM-1.1 违反任务规范:没有遵守任务的明确要求
- FM-1.2 违反角色规范:越界去做了不属于自己角色的事
- FM-1.3 步骤重复:重复此前已说过的内容,没有新信息
- FM-1.4 对话历史丢失:忽略或遗忘了之前的关键上下文
- FM-1.5 不识别终止条件:该结束时不结束 / 陷入循环

**智能体间失调类**
- FM-2.1 对话重置:无故重启对话,丢弃已有进展
- FM-2.2 未寻求澄清:信息不足却不主动询问
- FM-2.3 任务偏离:偏离了原本的任务目标
- FM-2.4 信息隐瞒:掌握了信息却没传给需要的 agent
- FM-2.5 忽视其他 agent 输入:无视协作者提供的相关输出
- FM-2.6 推理-行动不一致:推理得出一个结论,行动却相反

**任务验证类**
- FM-3.1 过早终止:任务未完成就结束
- FM-3.2 无/不完整验证:该验证的环节没验证或验证不充分
- FM-3.3 验证错误:执行了验证,但验证结论本身是错的

## 3.5 关键澄清:表现型(FM 标签)与归因(A/B)是**两个独立字段**

> 这一节回应一个真实且重要的方法论问题(见 `docs/attribution_vs_phenotype.md`)。
> **务必理解,否则会标错。**

一个常见误解是:"FM 标签决定了 A/B" —— 比如以为"标了 FM-3.2 就一定是 A 类"。
**这是错的。** 我们的 A/B 归因**不是**由 FM 标签机械推导出来的,而是对**这一条具体轨迹**
独立判断"是否违反了规范"。**同一个 FM 表现型,在不同轨迹里可以是 A,也可以是 B。**

以 **FM-3.2(无/不完整验证)** 为例,三条轨迹可以有不同归因:

- **轨迹甲**:系统设计了验证 agent、给了明确验证规范,但该 agent 没执行核查。
  → **违反了规范(该核查却没核查)→ A**,fm_type=FM-3.2。
- **轨迹乙**:系统里根本没有"必须验证"这条规范/角色,失败因为没人验证。
  → **没有可违反的规范 → 若仍失败,更接近 B(逃逸)**,或标"规范缺失/不确定"。
- **轨迹丙**:验证 agent 认真验证了,但因为**自身知识错误**得出错误验证结论。
  → 这其实更该标 **FM-3.3(验证错误)**,且若它忠实履职只是能力不足 → 可能是 **B**。

**所以标注顺序是**:先判 **Q-归因(A/B)** —— 只问"这条轨迹里,它违反了某条**明确存在的**
规范吗?";**再**(若 A)选最贴切的 FM 标签描述**表现形式**。不要反过来"先想 FM 标签、再由
标签推 A/B"。

**为什么这样设计(而不是给每个 FM 预设 A/B)**:
- 深层"根因"(是模型的锅还是架构的锅)本身常常不确定、可争论 —— 我们**不问根因**;
- 我们只问一个**可操作、可判定**的问题:**有没有一条预定义的规范被违反?**(V(τ) 是否为空)
- 这个"规范违反"判据绕开了根因的不确定性:不管深层是模型还是架构问题,只要**存在一条
  明确的规范且它被违反了**,就是 A;**没有任何规范被违反却仍失败**,就是 B(逃逸)。

**一句话**:`FM 标签 = 发生了什么(表现型)`;`A/B = 有没有违反明确规范(归因)`。两者独立填写,
A/B 不从 FM 标签派生。这也是为什么 A/B 必须由专家逐轨迹判断,**不能**用合成数据的 FM 标签
自动生成 —— 合成数据只有表现型标签,没有"这条轨迹违没违反规范"的归因标签。

## 4. 第三层:线索判断(靠什么发现的)

> **先完成第二层再做这一层,且不要回头修改第二层的答案。**

对每一个错误步骤,回答:

> ### Q-线索
> **你主要是靠什么发现这一步有问题的?**(可多选,但请指出**最主要**的一个)

- **【S+ 内部矛盾】** 它与自己的角色、任务要求、或其他 agent 的输出**直接冲突** ——
  不需要查任何外部知识,单看轨迹内部就能看出矛盾。
- **【S+ 内部冗余】** 它只是**重复**了之前的内容,没有新信息。
- **【S+ 内部断裂】** 它**忽略/丢失**了之前的上下文,或流程明显不连续。
- **【S+ 应有而缺失】** 它**本该做某件事却没做**(如本该核查却没核查)——你能看出"缺了什么"。
- **【S~ 下游后果】** 这一步单独看**看不出错**,你是**靠它后来被采信/被放大/导致下游出问题**
  才反推出它有问题的。
- **【S− 需查外部】** **只看轨迹内部完全看不出问题**;你是**靠外部医学知识 / 事实核查**
  才知道它错的(例如"这个剂量不符合临床指南""这个解剖描述与事实不符")。
- **【S− 异常一致】** 多个 agent **异常地一致**、毫无质疑或分歧,是这种"过度顺滑、无人反对"
  让你觉得可疑。

> 【S− 需查外部】这一项极其关键:勾选它意味着"这个错误在轨迹内部零信号"。
> 请仅在你确实需要动用轨迹之外的医学知识才能判断时勾选。

## 5. 第四层:责任结构(仅当标了多个错误步骤时)

| 字段 | 怎么填 |
|---|---|
| 主责步骤 | 你认为**最应该为这次失败负主要责任**的那一步(通常是最早违规处) |
| 连带责任 | 主责之后,**本应拦截/纠正却没有**的步骤(通常是验证环节) |
| 传播关系 | 若你能看出"哪一步的错误影响了后面哪一步",标出(源步骤 → 受影响步骤)对 |

## 6. 边界案例示例(帮助校准)

*这些例子说明归因判断与线索判断如何独立。*

**例 1(A + S~,不绑定)**:放射科 agent 违反角色去下了病理结论(违反 FM-1.2,**A**),
但你是看到后面的综合 agent 采信它、导致最终误诊,才回头发现的(**S~ 下游后果**)。
→ 归因 A、线索 S~。

**例 2(B + S+,不绑定)**:某 agent 忠实扮演心内科角色、流程完整(**没违反规范,B**),
但它陈述了一个错误的药物机制;恰好另一个 agent 当场给出了正确的相反陈述(**S+ 内部矛盾**)。
→ 归因 B(事实幻觉)、线索 S+。幻觉恰好被当场反驳,所以内部可见。

**例 3(B + S−,纯逃逸)**:某 agent 认真给出了诊断建议,引用了一个**听起来合理但实际过时**
的指南阈值,无人质疑、流程完整(**没违反规范,B**),你是查了最新临床指南才知它错的
(**S− 需查外部**)。→ 归因 B(医学知识误用)、线索 S−。这类是结构方法的盲区。

**例 4(A + S+ 缺失)**:验证 agent 该核查却直接放行(**违反 FM-3.2,A**),
你能直接看出"这里缺了核查动作"(**S+ 应有而缺失**)。→ 归因 A、线索 S+。

## 8. 信度与质量

- 每条轨迹 ≥2 位专家独立标注;≥20% 由 ≥3 位标注。
- 分层报告一致性(κ):归因(A/B)、FM 分类、线索(S+/~/−)、最早责任步 —— **分开报,不合并**。
- `不确定` 和专家间分歧**不是噪声,是数据**:尤其 B 类错误若归因分歧更大,
  说明"模型固有失败更难归责",这是一个重要发现,请如实保留、不要强行调和。

---

## 9. 分工建议(供团队决定)

- **第二层(归因 A/B、FM 分类、B 子类)**:**必须由临床专家判断** —— 涉及"称职 agent
  在此临床情境下该不该这么做"的专业判断。
- **第三层(线索 S+/~/−)**:偏认知/技术判断,可由受训标注员完成,**但 S−(需查外部医学知识)
  这一档需临床专家确认** —— 因为"是否真的需要外部医学知识"本身是医学判断。
- 若临床专家资源紧张:**优先保证第二层质量**(这是研究的入场券),第三层可作为加分项。

## 10. Pilot(正式标注前必做)

先标 10–20 条做校准:测每条耗时、测各维度 κ、收集专家对字段表述的反馈,再定稿正式协议。
若第三层线索判断在 pilot 中 κ 过低或耗时过长,考虑降级为"团队基于专家的第一、二层标注
事后推断"(但需注明并单独计信度)。
