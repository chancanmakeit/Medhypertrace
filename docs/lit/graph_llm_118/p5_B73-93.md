### #73 InstructBioMol（Nature Machine Intelligence 2025，B）
- 一句话：多模态 LLM（Llama-2-7B），实现自然语言、分子、蛋白质三者 any-to-any 对齐，可按指令理解与设计生物分子。
- 核心机制：冻结的模态编码器（分子 2D 图用 5 层 GIN、3D 用 Geoformer；蛋白质用 ESM2-35M、SaProt-35M）→ MLP 变换后拼接 → Transformer Encoder；motif prompt 与可学习查询 Q 作为 Decoder 初始输入，输出融合特征 Z；词表扩展（SELFIES 括号、蛋白质 `<p>` 前缀）加 `<MOL></MOL>` 等模态分隔特殊 token，Z 以 `<MOL> Z </MOL>` 形式嵌入输入。两阶段：持续预训练后指令微调（stage-1 大量低质量 → stage-2 小量高质量）。
- 关键数字：4 个模态编码器冻结，可训练参数 6.8B；靶点导向药物生成结合亲和力提升 10%。
- 【对 MAS 故障归因的可借鉴点】相关度 低。仅有两点形式上可参考：冻结编码器 + 可学习 query 做特征融合再注入 LLM；用特殊 token 界定"结构化 token 段"。分子/蛋白质与 MAS 轨迹无直接关联。

### #74 LLM4SD（Nature Machine Intelligence 2025，B）
- 一句话：用 LLM 从文献合成与从数据推断"可量化规则"，把分子变成规则特征向量，再用随机森林等可解释模型预测分子性质。
- 核心机制：知识合成 + 知识推断 → GPT-4 把每条规则写成可执行特征函数 → 传统 ML 做判别（LLM 只提候选描述子，"failsafe"）；不训练神经网络。
- 关键数字：量子性质 MAE 5.8233（前最优 11.2450，-48.2%，预印本口径）；Galactica 系显著优于通用 Falcon 系（领域预训练比规模更重要）。
- 【对 MAS 故障归因的可借鉴点】相关度 低-中。思路"LLM 提出规则 → 代码化成特征 → 轻量可解释模型"可作为 adapter 之外的另一条跨框架路线（例如把"是否重复上一条消息""投票是否与最终答案不一致"等规则代码化为图特征）【推断】；其"规则先由数据验证再保留"的 failsafe 思路也可对冲合成数据伪迹。

### #75 BioPathNet（Nature Biomedical Engineering 2026，B；非 LLM，GNN）
- 一句话：基于 NBFNet 的路径推理框架，用于生物医学知识图谱链路预测，学习"节点对"表征并给出可解释路径。
- 核心机制：广义 Bellman-Ford 动态规划，对头实体 u 与查询关系 q 并行算所有尾节点 v 的路径表征；引入背景调控图 BRG（只参与消息传递，不参与监督/负采样/损失）；节点类型感知的严格负采样；用对路径的偏导（边重要性之和近似）取 top-k 路径做解释。
- 关键数字：基因功能预测 MRR 0.464（KGE 平均 0.371，R-GCN 0.348），加 BRG 后 0.549；药物重定位 adaptation 的 AUPRC 平均提升 20.2%（对 TxGNN）。作者自述局限：无预训练、方差略高；路径嵌入不如节点嵌入便于下游复用。
- 【对 MAS 故障归因的可借鉴点】相关度 中。"在图上对（起点, 终点/查询）对做路径表征 + 回溯关键路径"与"从错误最终答案回溯到责任 agent/step"形式相近：可把"最终答案节点为查询、各 step 为候选尾节点"，用路径表征打分责任步【推断】。类型感知负采样可借来对付合成数据的模板伪迹（负例同类型采样）。注意它是端到端训练的 GNN，没有零样本跨图证据，且论文自述路径嵌入难复用。

### #76 PLM-interact（Nature Communications 2025，B）
- 一句话：把 ESM-2 改造成两个蛋白序列联合编码（类 NSP 的 cross-encoder）的 PPI 预测器，并可微调预测突变效应。
- 核心机制：输入 `[CLS, P1, EOS, P2, EOS]`，CLS 向量二分类；混合成对 MLM（15% 掩码）与分类损失，比例 1:10；全参数微调；两种蛋白顺序都用作数据增强。
- 关键数字：突变效应上，全层微调相比零样本 AUPR +150%、AUROC +36%；仅微调分类头"显著更差"。
- 【对 MAS 故障归因的可借鉴点】相关度 低。唯一可参考的是一条反面提示：交互知识需要进入深层编码器，仅训练头部/轻量层效果差——与"只做轻量 adapter 微调"的要求有张力（该结论来自蛋白场景，迁移性需自验）。

### #77 ProteinDT（Nature Machine Intelligence 2025，B）
- 一句话：用自然语言描述做文本引导的蛋白质设计（对比对齐 → 文本到蛋白表示映射 → 序列解码）。
- 核心机制：ProteinCLAP（ProtBERT + SciBERT 双塔对比学习，InfoNCE）；ProteinFacilitator（MLP 把文本表示映射到蛋白表示）；AR 或离散扩散解码器；潜在插值/优化做零样本编辑。
- 关键数字：SwissProtCLAP 441,013 对文本-蛋白；AR-Transformer + Facilitator 在 T=4 检索准确率 97.0%。
- 【对 MAS 故障归因的可借鉴点】相关度 低。仅"用预训练编码器 + 对比对齐缓解数据不足"的一般思路。

### #78 ChatMOF（Nature Communications 2024，B）
- 一句话：以 GPT-4 为核心的 ReAct/MRKL 式 agent（agent + toolkit + evaluator），完成 MOF 的检索、性质预测与逆向生成。
- 核心机制：question/thought/input/observation/final answer 循环；LLM 不微调、靠 prompt 与 few-shot；工具包括 pandas 检索、MOFTransformer 预测、遗传算法生成；代码出错最多自动重试 3 次；MOF 用"拓扑+构建块"文本基因编码。
- 关键数字：GPT-4 下检索/预测/生成准确率 96.9% / 95.7% / 87.5%。
- 【对 MAS 故障归因的可借鉴点】相关度 低（但可当"待归因对象"的一个例子）。其失败分析有参考价值：token 超限主要源于 LLM 代码能力不足（倾向打印整表），而非上下文窗口（16k 版本超限率并未下降）；GPT-3.5 在遗传算法中父子高度重复。可作为医学/科学类 MAS 中真实失败模式的素材。

### #79 InfoFlowEX（Cell Reports Medicine 2026，B）
- 一句话：整合 40 个异构生物医学信息抽取数据集为 BIE-Corpus，并提出任务条件式 schema 指令微调。
- 核心机制：本体引导对齐——BIOS 的 25 类实体 + 3 类关系，用冻结 CODER 嵌入 + MLP 分类器把各数据集原始标签投影到统一本体；schema 以 Python dataclass 表示（含定义与示例）；每个样本动态混入"正例 schema + 随机负例 schema"；自回归损失。
- 关键数字：对齐器在人工金标准上 macro F1 0.947；BIE-Corpus 184,000 样本 / 626,237 实体；消融显示去掉示例与负例 schema 均掉点。
- 【对 MAS 故障归因的可借鉴点】相关度 中。直接对应"不同 MAS 框架的角色/消息类型异构"问题：先建统一的角色/消息/动作本体（如 planner、critic、voter、tool-caller 等），用冻结嵌入 + 轻量分类器把各框架标签映射过去，再做图构建【推断】；schema-as-code + 随机负例 schema 的训练技巧可降低对某框架词汇的过拟合。其"语义相似度对齐可能忽略细粒度领域差异"的局限需要注意。

### #80 RareArena（Lancet Digital Health 2026，B）
- 一句话：从 PMC 病例报告自动构建的最大罕见病诊断基准（RDS 筛查 49,760 例 / RDC 确诊 22,901 例），评测 10 个 LLM。
- 核心机制：PMC-Patients 复现 → GPT-4o 筛选与抽取 → Orphanet 映射 → 截断到确诊检查之前并重述去泄漏 → 泄漏二次检测；GPT-4o 做同义/上位词 3 分制评判。
- 关键数字：GPT-4o RDS top-1 33.1% / top-5 56.9%；RDC top-1 64.2% / top-5 85.9%。作者自述局限：未评估推理过程正确性；GPT-4o 评判器可能引入偏见。
- 【对 MAS 故障归因的可借鉴点】相关度 低。可借鉴其"截断到关键证据之前 + 重述去泄漏 + 人工三维质检（泄漏/保真/复杂性）"的数据质量流程，用于缓解合成故障数据的模板伪迹【推断】。

### #81 VLPrompt-PSG（IJCV 2025，B）
- 一句话：用 LLM（GPT-3.5 + CoT）为全景场景图生成提供语言先验，缓解关系长尾。
- 核心机制：relation proposer（给主客体对提议可能关系）与 relation judger（逐三元组判定并给理由）离线生成文本特征，经双分支视觉-语言 prompter 的交叉注意力融合，MLP 门控自适应加权两路预测。
- 关键数字：R@100 52.4 / mR@100 53.7（前 SOTA HiLo 43.0 / 33.1）；稀有关系 mR@100 +13.8，高频 +2.3；换 Llama2-7B + BERT 仅降 0.4/0.5。
- 【对 MAS 故障归因的可借鉴点】相关度 低-中。"LLM 离线生成每条边/每个三元组的语义描述，再与图特征交叉注意力融合"可对应：用 LLM 给每条消息边写"此步是否合理"的描述作边特征（TAG 的边文本化）【推断】；长尾缓解对应稀有故障类型。

### #82 NLGraph（NeurIPS 2023，B）
- 一句话：用自然语言描述的 8 类图推理任务基准（标准版 5,902 题），评测 GPT-3/4 并提出 Build-a-Graph 与 Algorithmic 提示。
- 核心机制：随机图生成器控制难度；任务含连通性、环、拓扑排序、最短路、最大流、二分匹配、Hamilton 路径、模拟 GNN；提示基线包含 zero-shot/few-shot/CoT/0-CoT/least-to-most/自洽性。
- 关键数字：连通性的 chain/clique 虚假相关子集上性能比一般子集下降超过 40%（CoT 下 chain 降 44.50 个百分点）；BaG/Algorithmic 提示在 cycle 与 shortest path 上带来 3.07%–16.85% 提升；CoT 对 Hamilton 路径和拓扑排序基本无效。
- 【对 MAS 故障归因的可借鉴点】相关度 中-高（作为"文本化图让 LLM 读"路线的能力上限证据）。要点：(1) 复杂图任务上提示收益消失，few-shot 在 Hamilton/二分匹配上反而劣于 zero-shot；(2) LLM 依赖"节点提及频率"之类虚假相关——对应故障归因里"话最多的 agent 被判为责任方"之类的偏置风险；(3) 可借鉴其 chain/clique 式"对抗子集"设计来检验我们的模型是否只靠表面线索。这些既支持"需要显式图结构"，也警示纯 prompt 路线的上限。

### #83 GLBench（NeurIPS D&B 2024，B）
- 一句话：首个在有监督与零样本两种场景下统一评测 GraphLLM 方法的基准（7 个 TAG，12 个 GraphLLM + GNN/PLM 基线）。
- 核心机制：按 LLM 角色分 enhancer / predictor / aligner；统一 backbone 与划分；零样本设定为源/目标图及标签空间无交集（用 Ogbn-arxiv、Reddit 预训练，其余 5 图推理）；提出免训练基线 Emb w/ NA：冻结文本编码器编码节点与类别文本 + 邻域聚合 + 相似度分类。
- 关键数字：GraphLLM 在 6/7 数据集上同时取得最佳 Acc 和 F1；enhancer 最稳健，predictor 普遍弱于 GNN 且输出不可控；现有方法无明显 scaling law；Emb w/ NA 在全部数据集上超过 OFA、GraphGPT。纯 LLM 零样本很强但"疑似数据泄漏"。
- 【对 MAS 故障归因的可借鉴点】相关度 高。(1) 零样本协议（源图/目标图及标签空间无交集）可直接改造为"在框架 A 训、在框架 B 测"；(2) 免训练 Emb w/ NA 是必须对比的廉价基线；(3) 结论"结构与语义信息对零样本迁移都很重要"支持图 + 文本双通道；(4) 警示：LLM-as-predictor 路线（把图喂给 LLM 直接生成）在少量数据下输出格式不稳，需约束输出（如打分头而非生成）。

### #84 GraphArena（ICLR 2025，B）
- 一句话：基于 5 个真实数据源的 10 个图计算任务（4 个 P + 6 个 NP 完全，共 10,000 题），用四级评分区分正确/次优/幻觉/缺失。
- 核心机制：带重启随机游走采样子图；三步评分（路径提取 → 可行性检查 → 最优性验证）；还探索 CoT、指令微调、代码执行、测试时计算四条改进路线。
- 关键数字：大图 NP 任务所有模型准确率 <10%；幻觉随节点数近乎单调上升（GPT-4o 在 Diameter 任务上从 5 节点的 16% 升到 30 节点的 80% 以上）；GraphWiz 在 GraphArena 上仅 0.2%–1.2%（训练任务与格式不匹配）；Llama3-8b 指令微调后达到 Llama3-70b 级别，但对大图 NP 任务帮助有限。
- 【对 MAS 故障归因的可借鉴点】相关度 中-高。(1) "答对数字但解不可行"被计为正确的评测陷阱，对应故障归因中"猜中 agent 但 step 不对"——应分级评估 agent 级与 step 级（Who&When 本就如此）；(2) 图规模增大时幻觉上升，提示长轨迹（大图）需要截断/子图化；(3) GraphWiz 跨格式几乎失效，是对"零样本跨框架"的直接警示：在一种文本格式上训练的图推理模型难以迁移到另一种格式；(4) GraphToken（GIN 编码器 + LLM）表现介于 GIN 与 Gemma-7b 之间，说明图编码器注入并非万能。

### #85 G-reasoner（ICLR 2026，B）
- 一句话：图基础模型（34M 参数 GNN）+ 语言基础模型的统一框架，在多种图结构化知识上做推理，GFM 打分后交给 LLM 作答。
- 核心机制：QuadGraph 把异构图统一为四层（属性 / 实体 / 文档 / 社区）；查询相关 GNN（DistMult 消息、sum 聚合）与预训练文本嵌入联合编码拓扑和语义；类型特定预测头；训练目标含弱监督蒸馏项（冻结文本编码器的伪标签分布 KL）；GFM 按节点类型取 top-k 后经 prompt 交给 LLM（GPT-4o-mini）。
- 关键数字：6 个基准全部第一（如 HotpotQA 61.4/76.0）；同一模型在 HippoRAG / LightRAG / Youtu-GraphRAG 构造的不同图上零微调测试，均胜过各图专用检索器；G-bench (CS) 上每样本 0.2s（GFM-RAG 2.0s，KGP 89.4s）。训练用 277,839 个查询，且用多种图构造器建图。
- 【对 MAS 故障归因的可借鉴点】相关度 高。(1) QuadGraph 式"统一图接口"是跨框架零样本的关键：把各 MAS 框架轨迹统一为固定层级（如 agent 属性层 / 消息层 / 轮次层 / 共识层）；(2) "小型 GNN 打分选节点 + LLM 只读 top-k 证据"的两段式，正好对应"GNN 选候选责任 step，LLM 解释"；(3) 查询相关消息传递对应"以错误答案为查询"；(4) 用多种图构造器训练以获得跨构造泛化——对应用多个 MAS 框架/多种轨迹建图方式混合训练【推断】；(5) 蒸馏项可缓解标注稀疏（对应人工标注少）。差异：其任务是 QA 检索，非归因，且训练数据量大（约 28 万查询）。

### #86 Foresight-on-Graph（EMNLP 2026 主会/Findings 待核，B）
- 一句话：KBQA 证据检索框架，用"远到近"的有向反馈传播修正早期三元组打分，对抗逐跳贪心剪枝的短视。
- 核心机制：问题导向三元组编码器（冻结 Qwen3-Embedding-4B + 角色偏置 + 自注意力/交叉注意力）；前瞻打分器；分层 BFS（最多 3 跳）的 inward 有向子图；按距离递减顺序的反馈传播；LLM 管理记忆子图（低分三元组"暂时隐藏"可恢复，被 LLM 明确拒绝的永久屏蔽）；打分器以真值路径三元组做二分类 BCE 训练。
- 关键数字：CWQ 上 Hit 相对最强基线 +16.58%；WebQSP 平均 2.3 次 LLM 调用 / 2086 token（ToG 15.9 次 / 7018.9 token）；对已有方法错误的人工归因中"多跳错误累积"占 49%；用无向 GNN 替换前瞻传播效果明显更差。
- 【对 MAS 故障归因的可借鉴点】相关度 中。(1) 有向的"后向传播信号"与"从最终错误答案回溯到源头责任步"的方向吻合：用结果端信号沿有向边反传，修正早期 step 的责任分【推断】；(2) 消融证明有向传播不可被通用无向 GNN 替代，支持在轨迹图上保持时间有向性；(3) 其对"多跳错误累积"的人工归因本身就是一类"哪一跳出错"的故障归因，可作为类比。作者自述仅在两个通用 KGQA 基准上验证，未测医疗领域。

### #88 IPIGuard（EMNLP 主会 2026，B）【请细读项】
- 一句话：用"工具依赖图（TDG）"把 LLM agent 的规划与执行解耦，执行期只能按拓扑序执行计划内工具，从结构上防御间接提示注入（IPI）。
- 核心机制：
  - TDG 是 LLM 在执行前生成的 DAG：节点 = 一次工具调用（function_name + args），边 E(u,v) = v 依赖 u 的返回；严格 JSON 输出（`tool_calls`，每项含 id / function_name / args / depends_on）；规划期未知参数标 `<unknown>: data_type`，节点分确定性节点与待定节点；规划所用 LLM 可与执行所用 LLM 不同。
  - Argument Estimation：遍历到待定节点时，从依赖节点的返回中由 LLM 补全参数，转为已解析节点。
  - Node Expansion：借 CQRS 把工具分为只读的 Query Tools 与会改变环境状态的 Command Tools，执行期只允许追加 Query 类节点（Query Expanded Node，继承后继）。
  - Fake Tool Invocation：对"注入任务与用户任务工具重叠、只篡改参数"的情形，让 agent 先"调用新工具"处理注入指令，再由系统注入一条伪造的成功返回，使其回到用户原意。
  - 形式化：任务执行 = 工具调用序列 T，IPI 攻击把 Tᵤ 变成 Tᵤ′，其中 T_adv ⊆ Tᵤ′。
- 关键数字：AgentDojo（97 任务、629 个测试用例；4 种攻击 × 6 个 LLM）；GPT-4o-mini 主表平均 ASR 0.69%（最低基线 Tool Filter 2.06%），平均 UA 58.77%，BU 67.01%（无防御 68.04%）；开销约为无防御 2 倍 token（输入 14,605 vs 6,165）。作者局限：只防御干扰工具使用的 IPI，依赖较强规划能力。
- 【对 MAS 故障归因的可借鉴点】相关度 高（最直接的"agent 轨迹建模为图"先例，但要明确它不是学习型图模型）。可借鉴：
  1. 先例：agent 执行轨迹可用 DAG 表示，节点为"调用 + 参数"，边为数据依赖（`depends_on`），有现成 JSON 格式可直接参考；
  2. 节点类型划分：确定性/待定/已解析/Query 扩展，以及 Query vs Command（只读 vs 改状态）——可作为轨迹图节点类型特征，用于跨框架统一【推断】；
  3. "计划图 vs 实际执行图"对比：计划外调用、依赖断裂即偏离信号；故障归因可做"实际轨迹相对计划/期望依赖图的偏差定位"【推断】；
  4. 其结论"执行中心的结构约束比模型自觉更可靠"支持显式结构建模，但注意它是规划期结构约束，不涉及训练 GNN，也不做事后归因；
  5. 注入式攻击可作为故障注入的真实性参照（对应合成故障数据的构造方式）【推断】。

### #92 LLM4Hypergraph / Beyond Graphs（ICLR 2025，B）【请细读项】
- 一句话：首个超图理解基准（21,500 题、14 个任务），系统比较 7 种超图描述语言与 Hyper-BAG / Hyper-COT 提示。
- 核心机制：
  - 任务：8 低阶（超边计数、顶点计数、顶点度、顶点连接、连通顶点、可达性、最短路径、非连通顶点）、5 高阶（超边度、顶点集连接、顶点集在超边内、超边包含超边、超边间共享顶点）、2 同构任务（同构识别、结构分类）；5 种题型；合成超图 + 引文/蛋白质结构真实超图；除结构分类外每任务 1,500 样本，判定类正负 1:1。
  - 7 种超图语言：低阶 3 种（LO-Inc、N-Pair、Adj-Mat）、高阶 4 种（HO-Neigh、HO-Inc、N-Set、Inc-Mat），高阶语言保留超边的多顶点关联。
  - 提示：5 种配置（ZERO-SHOT / ZERO-HYPER-COT / FEW-SHOT / COT / COT-HYPER-BAG），Hyper-COT v1/v2/v3（v3：先想"由顶点连接的超边"再想"由超边连接的顶点"）。
  - 评测模型：ERNIE-Lite-8K、ERNIE-Speed-128K、Qwen-Long、LLaMA3-8B、GPT-3.5-Turbo、GPT-4o；主消融用 Qwen-Long。
- 关键数字（原文 Obs）：
  - 高阶语言在高阶/同构任务上全面占优；但在中/高难度低阶任务上低阶语言更好（高阶描述冗余、干扰二元对关联聚焦）；简单低阶任务上高阶语言占优。
  - 同构识别二分类约 50% 准确率，三分类结构分类用低阶语言约 30%；高阶语言 + 示例提示可提升到 60% 以上。
  - Hyper-COT v3 在结构分类上相对朴素 CoT 平均约 +4%，最高约 +9%（N-Pair、N-Set 编码）；Hyper-BAG 对低阶任务提升不明显，高阶任务约 +2%+（Vertex Set Connection +2.8%）。
  - 高阶任务 0→3-shot 约 +6%–9%；低阶任务无明显增益。超图规模越大表现越差，引文数据高阶任务最多约下降 13%。
- 【对 MAS 故障归因的可借鉴点】相关度 高。
  1. 超图文本化语言选择：当目标是"多方讨论/投票/共享上下文"这类真正的高阶关系时，应选保留超边成员集合的高阶语言（HO-Inc / N-Set / HO-Neigh / Inc-Mat 一类），而不是把超边拆成成对边（N-Pair / LO-Inc）；但若归因更依赖二元对关系（如 A 回复 B），低阶语言在中高难度任务上可能更优——最好两种视图并用并做消融【推断】；
  2. 能力上限：同构识别约 50%（≈随机二分类）说明 LLM 读文本化超图做"整体结构比较"很弱——这是跨框架拓扑差异场景的风险点；
  3. 规模瓶颈：超图越大越差，对应长轨迹/多 agent，需要子图抽取或分层；
  4. 提示可借鉴：Hyper-COT v3 的"超边→顶点→超边"双向两跳推理流程可用于做"文本化超图 + LLM"的对照基线；
  5. 局限：基准评的是计数/连通/包含等结构题，不是语义归因；任务为纯结构，无节点文本属性。

### #93 HyperG（SIGIR 2025，B）【请细读项】
- 一句话：把表格建成语义超图，并用 prompt 感知的超图学习模块（PHL）产生超边 embedding，作为 token 注入 LLM（LoRA 联合训练）做表格事实验证与问答。
- 核心机制：
  - 超图构建（SHC）：每个单元格为节点（|V|=M×N），每行、每列以及整张表（caption）各一条超边（|E|=M+N+1），关联矩阵 H ∈ R^{|V|×|E|}；节点/超边语义用 BERT tokenizer + embedding 编码；
  - 上下文增强：用 LLM 为 caption、每行、每列生成自然语言描述，处理 N/A、缩写等稀疏单元格；
  - PHL 每层两步：node→edge（K 头超图注意力，残差 + LN + FF，并与原超边语义拼接）；edge→node（以 prompt 中任务询问 ω 的 embedding 为 query 与超边交互，把任务相关信息传回节点）；
  - 注入 LLM：取最后一层"表超边 embedding"h_{e_T}^L，经两层线性 + ReLU 的 projector 映射到 LLM token 维度，插入 prompt 的 "Table Hyperedge" 占位符，与 prompt token 拼接；PHL + projector 与 LoRA（rank=8, alpha=32, dropout=0.1，仅 QKV）联合监督微调，自回归 NLL 损失。
- 关键数字：比每组次优结果平均高 TFV +1.73% acc、TQA +2.43% denot. acc；LLaMA3-8B + HyperG（仅增加约 189M 参数）与 70B 序列化方法性能相当；行/列随机打乱下 accuracy 方差仅 0.0109 / 0.00043；消融：去掉 PHL 降 6.24% acc，用经典 HGNN 替代 PHL 降 4.50%，去掉 inquiry embedding 精度降 5.76%；大表上 recall 下降（作者归因于超图层数有限），中/大表 Dater recall 更优。
- 【对 MAS 故障归因的可借鉴点】相关度 高（超边作为 token 注入 LLM 的最接近先例）。
  1. 注入方式：超边 embedding → 两层 MLP projector → 占位符 token，LoRA 微调只动 QKV，参数增量小（约 189M）；可直接搬到"每个讨论/投票超边 → 一个或多个软 token"；
  2. 任务感知传播：把"任务询问"作为 query 做 edge→node 注意力——对应以"最终错误答案/问题"为查询定位责任 step；
  3. 顺序不变性：超边天然无序，适合"同一轮并行发言/投票"这类无序集合；但 MAS 轨迹有强时间序，需另加时序编码【推断】；
  4. 局限：只注入了单个"表级超边"embedding（压缩度高，可能丢细节）；大表上 recall 下降；仅在 TabFact / WikiTableQuestions 上验证，无跨域零样本结论；PHL 是需要训练的模块，跨框架迁移要靠统一图 schema（如 #85、#79 的思路）。

## 本段综合

### (a) 与该 idea 最相关的 3–6 篇及理由
1. **#92 LLM4Hypergraph**：唯一直接回答"LLM 能不能读懂超图、用什么语言写"的基准；给出语言选择（高阶 vs 低阶）、同构识别约 50%、规模退化、Hyper-COT 等能力上限与失败条件。
2. **#93 HyperG**：超边 embedding → projector → 软 token 注入 LLM + LoRA 的完整可复用范式，且有 HGNN 替换与去 PHL 的消融。
3. **#88 IPIGuard**：agent 执行轨迹建模为 DAG（工具调用节点 + depends_on 边）的明确先例，节点类型（确定/待定/Query/Command）与"计划 vs 执行"偏差思路可迁移；非学习型。
4. **#85 G-reasoner**：统一图接口（QuadGraph）+ GNN 打分 + LLM 的两段式，以及"同一模型在不同图构造器产出的图上零微调"的跨图泛化证据，与零样本跨框架诉求最接近。
5. **#83 GLBench**：GraphLLM 的零样本协议与免训练强基线（Emb w/ NA），以及"predictor 路线不稳、无明显 scaling law"的结论。
6. **#82 NLGraph / #84 GraphArena**（并列）：文本化图的推理上限与虚假相关/幻觉证据；GraphArena 的分级评分与 GraphWiz 跨格式失效尤其相关。

### (b) 可直接搬用的技术组件清单
- 超边 → LLM：`超边 embedding → 两层 Linear+ReLU projector → prompt 占位符 token`，LoRA（rank 8, alpha 32, 仅 QKV）联合训练（#93）。
- 任务查询感知的 edge→node 注意力（以最终答案/问题 embedding 作 query）（#93，#85 的查询相关 GNN 同理）。
- 超图构造模板：节点 = 基本单元，超边 = 共享同一语义分组（行/列/整体）；MAS 对应"一次讨论 / 一轮投票 / 共享上下文"为超边【推断】（#93 构造思路）。
- 超图文本化语言：HO-Inc / N-Set / HO-Neigh（高阶）与 N-Pair / LO-Inc（低阶）并存做消融；Hyper-COT v3 的"超边→顶点→超边"提示（#92）。
- 统一图接口（分层节点类型 + 跨层特殊边）+ 多种图构造器混合训练（#85）；本体对齐 + schema-as-code + 随机负例 schema（#79）。
- 以冻结文本编码器 + 邻域聚合的免训练零样本基线（#83），冻结 Qwen3-Embedding 作三元组/消息编码（#86）。
- 弱监督蒸馏项：冻结文本编码器的伪标签分布与 GNN 预测分布做 Bernoulli-KL（#85），可缓解人工标注稀少。
- 工具/动作依赖 DAG 的 JSON 格式（id / function_name / args / depends_on）与节点类型划分（#88）。
- 后向（果→因）有向信号传播 + 记忆子图的"暂时隐藏/永久屏蔽"机制（#86）。
- 节点类型感知的严格负采样（#75）；干预式诊断（掩码关键边/替换身份）（#90）；四级评分（正确/次优/幻觉/缺失）与可行性检查（#84）。
- 冻结模态编码器 + 可学习 query 的融合模块与模态分隔特殊 token（#73）。

### (c) 对该 idea 的反面证据 / 风险
- **LLM 读图本身能力有限**：同构识别约 50%，结构分类用低阶语言约 30%（#92）；复杂图任务上 CoT/few-shot 收益消失甚至起反作用（#82）；大图 NP 任务准确率 <10%、幻觉随图规模单调上升（#84）。长轨迹/多 agent 大图会退化（#92 规模 Obs 9：引文数据高阶任务最多下降约 13%）。
- **虚假相关**：LLM 在连通性上可能靠节点出现频率，chain/clique 子集性能降幅超过 40%（#82）——合成故障数据里的模板伪迹同样可能被利用，而图通道不一定能杜绝。
- **GraphLLM 的 predictor 路线不稳**：少量数据下输出格式不可控，普遍弱于 GNN；现有方法无明显 scaling law；免训练基线可超过专门的零样本 GraphLLM（#83）。这意味着"训一个超图大模型"的收益需要强基线对比，不能默认成立。
- **跨格式迁移风险**：GraphWiz 在 GraphArena 上仅 0.2%–1.2%（训练任务/格式不匹配）（#84）；HyperG、BioPathNet 等都是在单一数据形态上训练，没有跨域零样本证据（#93、#75）。我们的"跨 MAS 框架零样本"没有本段中的直接成功先例；最接近的是 G-reasoner 对不同图构造器的零微调泛化（#85），但那是同任务（QA 检索）下的结果。
- **轻量 adapter 可能不够**：PLM-interact 中仅微调分类头显著更差（#76，蛋白场景）；HyperG 大表上 recall 下降，作者归因于超图层数有限（#93）。
- **信息压缩**：HyperG 只注入单个表级超边 embedding（#93），多方讨论的细节可能丢失。
- **GNN 自身问题**：低同质性图上深度 GNN 容易过平滑、嵌入不可分（#91，聚类任务上的证据，迁移性待验证）。
- **没有直接的"agent 级/step 级归因"证据**：本段无任何论文评测故障归因；#88 是防御而非归因，#86 的"多跳错误归因"是人工分析。
- **超图收益需单独证明**：#92 显示高阶语言只在高阶任务有优势，低阶任务上反而更差；若 MAS 归因主要依赖二元（回复）关系，超边的增益可能有限。

### (d) 可能成为直接竞争者 / 必须对比的基线（本段内）
- **纯文本序列化 + 强 LLM（含 Hyper-COT / Build-a-Graph 类提示）**：即 #92/#82 的提示方案作为"LLM 读文本化(超)图"的零训练基线，同时也是"训 LLM 读轨迹"路线的最低对照。
- **免训练 Emb w/ NA**（#83）：冻结编码器 + 邻域聚合 + 相似度打分，对应"不用 LLM 微调的图方法"下限。
- **HyperG 式"超边 token + LoRA"**（#93）：若我们的方法也采用该注入方式，则需要对比与纯文本序列化 LoRA（同骨干）的差距，以及与经典 HGNN 替代的差距（#93 消融已提供对照写法）。
- **G-reasoner 式"GNN 打分 + LLM 读 top-k"**（#85）：两段式的直接竞品；FoG（#86）可作为"训练打分器 + 有向反馈"的图 agent 对照。
- **Tool-dependency-graph / 执行图偏差法**（#88）：作为"无需训练的结构规则"基线（计划外/依赖断裂检测），注意需要自行适配到事后归因。
- **GraphToken 式 GIN 编码器 + LLM**（#84 中被评测的混合基线）：说明"图编码器 + LLM"本身并非新颖，需要在超图、跨框架、语义通道上体现差异。
