## C · 文本属性图 × LLM

### #94 TAPE（ICLR 2024，C 文本属性图×LLM）
- 一句话：用 LLM 对每个节点做零样本分类并生成文本解释，再由微调的小 LM 把解释转成向量特征，供 GNN 做节点分类（首个 LMaaS 兼容的 LLM→TAG 框架）。
- 核心机制：三阶段解耦流水线——(1) 一次 LLM 调用得到 top-k 预测列表 + 解释；(2) 分别微调两个 DeBERTa（编码原文、编码解释）并把 top-k 预测 one-hot 后线性变换，得 h_orig / h_expl / h_pred，特征冻结；(3) 三个 GNN 分别吃三种特征，预测取平均。LM/LLM 不参与 GNN 训练，只需文本 API。理论上给出：解释若对 LLM 隐表示忠实且对小 LM 非冗余，则作为特征严格降低条件熵。
- 关键数字：ogbn-arxiv 上 RevGAT 0.7750±0.0012，训练时间约为 GLEM 的 1/2.88；新建 tape-arxiv23（46,198 节点/78,548 边，晚于 GPT-3.5 知识截断）用来检验标签泄漏，RevGAT 0.8423±0.0256。
- 【对 MAS 故障归因的可借鉴点】相关度：中。
  - "LLM 逐节点（逐 step）给出判断+解释 → 小 LM 编码 → GNN 做全局聚合"可作为一个解耦、对闭源 API 友好的 pipeline（推断：把每步"是否出错"的 LLM 判断当 h_pred/h_expl）。它与"让一个 LLM 读整条轨迹"不同：LLM 只做局部判断，结构聚合交给 GNN。
  - 三种特征分别训 GNN 再平均、以及 prompt 变体鲁棒性实验（精度 0.7660–0.7750）可借来检验"模板伪迹"；tape-arxiv23 的"用晚于知识截断的新数据检验泄漏"思路可对应"留出全新 MAS 框架/新医学任务"的评测。

### #95 MolCA（EMNLP 2023，C 文本属性图×LLM）
- 一句话：用 Q-Former 跨模态投影器把分子 2D 图编码器的表示映射到 LM（Galactica）的文本空间，LM 同时看 1D SMILES 与 2D 图，并用 LoRA 做下游适配。
- 核心机制：5 层 GINE 图编码器（对比学习预训练）+ Q-Former（N_q=8 个可学习 query，cross-attention 抽图特征）；阶段 1 联合 MTC（InfoNCE，τ=0.1）/ MTM / MCap；阶段 2 接冻结 LM，Q-Former 输出作软提示；阶段 3 LoRA 微调（单模态适配器）。
- 关键数字：CheBI-20 / PubChem324k 分子描述 BLEU-2 分别 +2.1 / +7.6；2D 图+1D SMILES 联合优于任一单模态（MoleculeNet 6 任务 scaffold split 平均 ROC-AUC 72.1→74.0）；"数官能团"消融显示 LM 确实学到结构信息。
- 【对 MAS 故障归因的可借鉴点】相关度：中。
  - Q-Former 用固定个数（8）query 把任意大小的图压成固定长度软提示，可直接解决"不同 MAS 框架步数/agent 数差异大"的变长问题（推断）。
  - "文本（1D）+ 图（2D）并用优于单独使用"支持"轨迹文本 + 图结构"双通道；"功能团计数"式探针任务可用来检验模型是否真的用到了结构而非只读文本。
  - 局限：原文自述数据规模（324k 对）远小于视觉-语言预训练；对齐依赖大量图-文对（此点对 MAS 低资源不利）。

### #96 GIMLET（NeurIPS 2023，C 文本属性图×LLM）
- 一句话：把 T5 统一扩展到"图+文本指令"，通过广义位置嵌入把分子图结构和指令一起编码，实现无需下游标注的指令式分子零样本学习。
- 核心机制：图节点与文本 token 拼成一个输入序列，不引入额外 GNN；相对位置偏置 b(i,j) = 文本相对位置 + 图节点最短路距离（沿路径对边特征均值池化，Graphormer 式）+ 跨模态特殊 <Cross>；解耦注意力掩码：图 token 只能看图 token，指令 token 可看全部；输出统一为文本生成（Yes/No 或数字）；指令预训练用 1048 个 ChEMBL 生物活性任务 + 13 个理化性质任务。理论上：距离型相对位置嵌入的表达力不弱于 1-WL。
- 关键数字：ChEMBL Zero-Shot ROC-AUC 0.7860（基线多在 0.5 附近）；参数仅 64M，优于 1.3B 的 Galactica；消融去掉解耦掩码在多数数据集下降，去掉指令中的任务解释 bace 0.6957→0.5416。
- 【对 MAS 故障归因的可借鉴点】相关度：高（作为"保留结构且不另设 GNN"的架构备选）。
  - 把轨迹图的结构（最短路距离、边类型：reply-to / vote / 共享上下文）以注意力偏置/位置编码的形式直接注入 LM，而不是展平成文本；这是与"文本读轨迹"明显不同的结构保留方式。
  - 零样本靠"指令中写明任务背景"：去掉任务解释后性能大跌，提示应把"当前 MAS 框架的角色/拓扑说明"写进指令来支撑跨框架迁移（推断）。
  - 注意（推断）：GIMLET 里一个原子=一个 token，而 MAS 节点是长文本消息，需先把每个节点压成 1 个或少量 token 再套用该机制；原文的零样本是"同一分子图域内换新任务"，不是换图域。

### #97 TaLK（EMNLP Findings 2026，C 文本属性图×LLM）
- 一句话：首个在 LM–GNN 联合训练管线下做 TAG 数据集蒸馏的方法。
- 核心机制：内层保留显式 LM–GNN 联合训练，外层用图感知 NTK（SNTK）+ 核岭回归闭式预测替代可训练 GNN；batch-wise gradient injection 让 mini-batch 仍忠实于全局外层目标；合成数据 structure-free（A'=I，标签固定，只优化 token-embedding 级特征 X'）。
- 关键数字：Arxiv 上 1% 合成数据达到全集性能的 97%；超参搜索加速 12.63×（Photo）/17.66×（Arxiv）。
- 【对 MAS 故障归因的可借鉴点】相关度：低。仅在需要压缩合成训练集 / 加速超参搜索时有参考价值；原文自述蒸馏产物不是人类可读文本，且仅针对半监督节点分类。

### #98 TEA-GLM（NeurIPS 2024，C 文本属性图×LLM）
- 一句话：把 GNN 表示对齐到 LLM token embedding 空间，再用一个线性投影层把中心节点表示变成 K 个 graph token 喂给冻结 LLM，实现跨数据集、跨任务（节点分类→链接预测）的零样本图学习。
- 核心机制：(1) 先对 GNN（2 层 GraphSAGE，输入为 BERT 编码的节点文本）做增强自监督预训练：实例级对比（随机删边 RE + 特征掩码 MF 两个视图，InfoNCE）+ 特征级对比（取表示的各"维度列"做对比；先用 LLM token embedding 的 PCA 主成分 C 把 GNN 输出投影到 LLM 语义坐标轴，要求 F_U=F_L），总损失 ½(L_ins+L_fea)；(2) 冻结 GNN，只训一个线性投影器 f_Linear 把中心节点表示映射成 K 个 token，填进指令模板的 <graph> 占位符；模板中含"备选答案集合 {ans}"，让模型学"按任务从给定集合里选答案"而非记住某数据集的答案；(3) LLM（Vicuna-7B-v1.5）全程冻结；投影器仅在单一数据集上训练 1 epoch（lr 1e-3），其余数据集/任务直接零样本测试。节点级只用中心节点表示（GNN 消息传递已带邻域信息），边级先池化两端点再映射，图级类似——同一个 K 个 token 统一三种层级。
- 关键数字：跨数据集节点分类 6 个测试集全最优（Pubmed 0.848、Cora 0.202、Children 0.271、History 0.528、Photo 0.497、Sports 0.404）；跨任务链接预测 AUC 在 8 个数据集中 7 个最优（Arxiv 0.657、Pubmed 0.689），Sports 上略逊 LLaGA（0.553 vs 0.597），OFA 出现负迁移（<0.5）。消融：去掉特征级对比（w/o FC）在训练集上略升、在未见数据集/未见任务上明显下降；答案合法率在未见数据集稳定 ~92–100%，LLaGA 在 Photo 77.8%、Cora 79.9%；TEA-GLM 在训练集上的监督性能不如 LLaGA/OFA（拟合更强≠零样本更好）。
- 【对 MAS 故障归因的可借鉴点】相关度：高（本段最直接对应用户"GNN 表示对齐 LLM token 空间零样本"的论文）。
  - 可借：特征级对比 + PCA 主成分对齐（原文消融证明它是跨数据集/跨任务零样本的关键，而不是实例级对比）；"冻结 LLM + 线性投影 + 固定 K 个 graph token"天然满足"最多轻量 adapter 微调"；指令里带候选集（对应"候选 agent 列表 / 候选 step 编号"）以统一 agent 级与 step 级两种任务（推断：不同框架 agent 名字不同，用候选集作答而非记忆标签）；只训一个小投影器即可，参数量与过拟合风险小。
  - 原文有一个有用的细节：节点文本只给 title（不给 abstract）反而让 LLM 更多利用图信息——对应"别把整条轨迹文本全塞进 prompt，否则 LLM 会绕过 graph token"（推断，对设计"图通道是否真被使用"的消融有启发）。
  - 局限见"本段综合 (c)"：迁移只在节点语义相近的 TAG（引文/电商）之间验证，且零样本绝对精度不高。

### #99 HyperBERT（EMNLP Findings 2024，C 文本属性图×LLM）
- 一句话：在 BERT 每一层里并行混入超图感知（HGNN）分支，同时建模文本语义与超图高阶结构，做文本属性超图（TAHG）的节点分类。
- 核心机制：每层 = 语义分支（BERT 层，取 [CLS]）+ 结构分支（在"节点中心上下文超图"——仅含节点 i 所属超边的子超图——上运行 HGNN：σ(D⁻¹HWB⁻¹Hᵀ X Ψ)），二者相加并加到每个 token 的语义嵌入上（非"先 LM 再 GNN"的级联）；自监督知识对齐损失 L = λ₁L_semantic + λ₂L_structural + λ₃L_align（λ 均为 1，τ=0.2；正例为同超边邻居，负例为 batch 内其余节点；对齐项双向）；下游冻结编码器，只训 2 层 MLP。预训练 6 层、dim 512、20,000 steps、单卡 A100。
- 关键数字：5 个基准全部 SOTA（Cora 64.5%、Pubmed 78.9%、DBLP-A 82.3%、Cora-CA 69.2%、IMDB 49.7%）；消融（Pubmed）去对齐损失 −15.8%（至 63.1%），HGNN 换成普通 GNN −7.7%，不预训练 −7.4%。
- 【对 MAS 故障归因的可借鉴点】相关度：中高。
  - 超边=一次多方讨论/投票/共享上下文，节点=消息或 step，直接对应其数据构造方式（共著/共引/同演员=一组节点共享一条超边）。
  - 可借：逐层混合（每层把结构嵌入加到 token 嵌入上，而非展平为文本）；节点中心上下文超图（只取该节点所属超边，天然支持变长/变拓扑）；三项对比损失中"同超边邻居为正例"的自监督目标，可在无标注轨迹上做预训练以缓解人类标注稀缺（推断）。
  - 局限（原文）：只评估了节点分类，未验证超边预测等；全部在小规模、同数据集内（直推式）评测，没有零样本跨数据集实验。

## E · 图 RAG

### #100 LinearRAG（ICLR 2026 Poster，E 图 RAG）
- 一句话：用无关系的分层图 Tri-Graph（实体/句子/passage 节点，仅 spaCy NER + 语义链接）替代需要 LLM 关系抽取的知识图，索引零 LLM token、线性扩展。
- 核心机制：边只有"句子–实体提及"和"passage–实体包含"两个稀疏矩阵；检索阶段 1 在句子–实体二部图上做语义传播激活实体（a_q^t=MAX(Mᵀ(σ_q⊙(M a_q^{t−1})), a_q^{t−1})，≤4 次迭代，阈值 δ 动态剪枝防语义漂移）；阶段 2 在 passage–实体图上做个性化 PageRank，混合初始化。动机诊断：GraphRAG 常输给朴素 RAG，根因是关系抽取带来局部不准确与全局不一致。
- 关键数字：2Wiki Contain-Acc 70.20 / GPT-Acc 63.70；索引耗时 249.78s，prompt/completion token 均为 0（LightRAG 索引 4933.22s，35.52M/51.16M token）；索引时间比传统方法减少超过 77%。
- 【对 MAS 故障归因的可借鉴点】相关度：低中。启示是"图的边应来自确定性、不依赖 LLM 抽取的结构信号"——MAS 日志里谁回复谁、第几轮、谁投了票都是现成的确定性边，不需要 LLM 抽关系，从源头避免 LinearRAG 指出的关系噪声；带阈值剪枝的传播/PPR 可作为"无训练图传播"基线。

### #101 GraphRAG-Bench（ICLR 2026，E 图 RAG）
- 一句话：回答"何时该用图做 RAG"的基准：医学（NCCN 指南）+ 小说两个高信息密度语料，4 级任务难度，构图—检索—生成分阶段指标。
- 核心机制：任务 L1 事实检索 / L2 复杂推理 / L3 上下文摘要 / L4 创造性生成，难度按证据子图的结构属性（实体密度、路径长度、推理距离）校准而非 hop 数；对 7 个 GraphRAG 框架与基础 RAG 做比较；指标含图质量（平均度、聚类系数）、检索（Context Relevance、Evidence Recall）、生成（Accuracy、Faithfulness、Evidence Coverage）。
- 关键数字：L1 上基础 RAG 的 Evidence Recall 高达 83.2%（小说集），图的冗余反成噪声；prompt 长度随任务复杂度从 7800 膨胀到 40000 token；Global-GraphRAG 平均约 3.3×10⁵ token，HippoRAG2 约 10³ 最省。结论：简单事实检索用普通 RAG，复杂推理/摘要/创造性任务图才占优。
- 【对 MAS 故障归因的可借鉴点】相关度：中（方法论）。评测应按难度分层（单步明显错误 vs 多 agent 错误级联/长链），并报告"图是否在难例上才有优势"；分阶段评估（构图质量/检索/生成）对应"图构造质量→结构编码→归因输出"逐段消融；同时给出风险参照：图并不总是比朴素方案好。

### #102 LogicRAG（AAAI 2026，E 图 RAG）
- 一句话：不预建图，推理时把查询分解为子问题 DAG，拓扑排序后逐个检索—回答，用滚动记忆和同层合并做剪枝。
- 核心机制：LLM few-shot 分解子问题并推断依赖边，拓扑排序验证无环并线性化；贪心单遍求解（检索以父节点答案为条件，消除"检索需先解决依赖、解决依赖需检索"的递归死锁）；上下文剪枝（滚动摘要记忆）+ 图剪枝（同 rank 子问题合并成统一查询）；无训练、无损失函数。
- 关键数字：2WikiMQA 64.7/62.5（比 HippoRAG2 的 50.0 高 +14.7）；MuSiQue 30.4/37.5；查询时 9.83s / 1777.9 tokens（HippoRAG2 5.89s/2809.2，GraphRAG 13.05s/4699.8），但完全省去离线建图。发现：4-hop 问题的平均检索轮数少于 3-hop，LLM 对超长复杂查询会过早自信作答。
- 【对 MAS 故障归因的可借鉴点】相关度：中。
  - 作为竞争思路：证明"推理时由 LLM 动态抽取结构"可超过预建图方法，即"把结构写进提示/让 LLM 自己建 DAG"是一条不需训练图模型的强基线（推断：对应"LLM + 显式结构序列化"基线）。
  - 可借：对 MAS 轨迹做依赖 DAG 的拓扑线性化，使"因果先后"在输入中显式；"LLM 过早自信"可对应归因时的位置偏置检查（推断）。

### #103 MemGraphRAG（KDD 2026，E 图 RAG）
- 一句话：用共享三层全局记忆（本体/事实/段落）支撑的多智能体协作来建图（抽取、冲突检测、冲突解决三类 agent），并配记忆感知分层检索。
- 核心机制：诊断 GraphRAG 退化的根因是"孤立的局部抽取"→ 主题无关、逻辑不一致、结构碎片化；新 schema 需频次≥τ 才晋升，只有对齐稳定 schema 的事实才激活；A_det 异步扫描冲突，A_res 回溯来源段落裁决；检索三阶段（多层记忆过滤→结构感知节点初始化，含枢纽抑制项 1/log(deg+1)→PPR，λ=0.5）。
- 关键数字：生成准确率平均 59.25%，领先最强基线 LinearRAG（57.15%）+2.10 个百分点；初步实验：GFM-RAG 召回 84.3% vs RAG 71.8%，但相关性 38.5% vs 62.9%；过滤 40% 低频 schema 三元组反而略提升精度；去掉冲突解决在 HotpotQA 降幅最大（全模型 69.40%→66.95%）。
- 【对 MAS 故障归因的可借鉴点】相关度：低中。(1) 它本身是一个多 agent 系统（抽取/检测/解决角色，含冲突裁决），可作为被诊断的 MAS 实例（推断）；(2) "每个事实回溯到来源段落"的溯源设计 ↔ 每个归因结论回溯到具体消息；(3) 图召回高但相关性低的现象提示：图结构会带来噪声，需要过滤。

### #104 HyRAG（KDD 2026，E 图 RAG）
- 一句话：首个面向图基础模型的双曲 RAG：在庞加莱球中建知识索引、做粗/细粒度检索、双路径融合，zero-shot 下增强冻结的 GFM 骨干。
- 核心机制：HKI 用 SBERT 编码 + 映射网络 + 指数映射入庞加莱球，训练含关系旋转下的双曲距离损失、双曲蕴含锥角度损失、径向正则；MR 用 LLM 把查询改写为粗粒度 q_a 与细粒度 q_s，粗侧用双曲距离下的 MMR 扩展、细侧用角度违例分数选下位概念；DF 特征层加权注入 + 结构层按预测熵置信度门控，最终 p_final=p_q+α·(H_q/log C)·p_know（原预测不确定时才大量注入外部知识）。GFM 参数冻结，仅训练 HKI 映射网络。
- 关键数字：7 个跨域数据集节点分类平均 64.16%（GraphCLIP 原实现 62.00%，欧氏 RAGRAPH 63.34%）；链接预测 Cora +1.08%、CiteSeer +1.41%；HKI 换欧氏索引平均 −1.99%。
- 【对 MAS 故障归因的可借鉴点】相关度：低中。(1) 轨迹天然层级（任务→轮次→agent→step）若呈树状可考虑双曲嵌入，但原文增益仅 1–2 个百分点，且外部库是常识 KG（推断：是否值得需自行验证）；(2) 熵门控融合"仅在基础预测不确定时注入补充信息"可借鉴为置信度门控；(3) 冻结骨干 + 只训小模块的 zero-shot 设置与用户目标一致。

### #105 GraphRAG-R1（WWW 2026，E 图 RAG）
- 一句话：用"过程约束的基于结果的 RL"（改版 GRPO + rollout-with-thinking）训练 LLM 自主分解多跳问题、按需调用检索工具并推理。
- 核心机制：特殊 token 标记检索调用；retrieval-masked loss（检索内容 token 不计入策略梯度）；组优势 A_i=(r_i−μ_r)/σ_r；奖励：format（0.5/0）、PRA（Progressive Retrieval Attenuation：R_n=R_{n−1}+R_0·k^{n−1}，鼓励必要检索并随深度衰减，防浅层检索）、CAF（Cost-Aware F1：F1×a×e^{−bN}，实现 a=2,b=0.1，防过度思考）；三阶段训练：SFT 冷启动→format+PRA→CAF+format；混合图-文本检索（三元组+文本片段）；骨干 Qwen-2.5-7B + LoRA(r=16)，检索器 HippoRAG2。
- 关键数字：F1 HotpotQA 38.00 / MuSiQue 20.06 / 2Wiki 32.24 / PopQA(领域外) 35.04，均最优；只训一次、训练时只见过 HippoRAG2，换接 Naive RAG +18.04%、LightRAG +38.37%、KGP +36.25%、HippoRAG2 +22.40%（平均 +3.52%–38.37%）。去掉 CAF 检索次数上升但 F1 反降（类 reward hacking）；去掉冷启动或不分阶段训练显著掉点。
- 【对 MAS 故障归因的可借鉴点】相关度：中。
  - 重要澄清：这里的"过程约束"约束的是检索次数/行为（PRA、CAF 都以检索次数 N 为变量），并不是对每个中间推理步骤的正确性打分；所以它不能直接当"逐步归因的 step 级监督"（推断）。
  - 可借：把归因器做成"逐步查看轨迹的工具调用 agent"（查看某 step、某 agent 消息），用 GRPO + 成本感知奖励训练；三阶段（冷启动→行为塑造→优化）防多目标梯度冲突；"训练时只见一种检索器，推理时换检索器仍有增益"的迁移现象可类比"训练时一种 MAS 框架，推理换框架"（推断，属于 LLM-agent 路线，与"图大模型"路线区别较小）。

### #108 GFM-RAG（NeurIPS 2025，E 图 RAG）
- 一句话：首个用于 RAG 的图基础模型：一个 8M 参数的 query-dependent GNN 检索器，单步完成多跳检索，经两阶段训练后可零微调泛化到未见数据集。
- 核心机制：KG-index（LLM 做 OpenIE 抽三元组 + 稠密嵌入做实体消解加语义等价边 + 实体→文档倒排）；查询用句子嵌入编码为 q，查询中提到的实体初始特征置为 q，其余为零；6 层消息传递（沿用 NBFNet），关系嵌入同样由句子嵌入初始化并由 2 层 MLP 逐层更新，三元组层用无参 DistMult 生成消息，实体层求和聚合后过单线性层；MLP+sigmoid 输出每个实体对该查询的相关性；泛化原理：query/实体/关系都由同一个冻结句子嵌入模型初始化到同一空间。训练：无监督 KG 补全预训练（mask 三元组头/尾生成合成查询）→ 有监督文档检索微调；损失 L=α·L_BCE+(1−α)·L_RANK，α=0.3（ranking 项缓解目标实体稀疏造成的梯度消失）；文档分数用实体文档频次倒数加权后经倒排索引累加。
- 关键数字：HotpotQA/MuSiQue/2Wiki 上 R@2 为 78.3/49.1/90.8，超过 IRCoT+HippoRAG 约 16.8%/8.3%/19.8%；单次检索 0.06–0.12 秒（IRCoT+HippoRAG 约 3 秒）；七个跨领域数据集零微调 R@5 平均超过 HippoRAG 18.9%；训练数据 60 个 KG、>1400 万三元组、70 万文档；性能服从 scaling law z ∝ 0.24x^0.05 + 0.11y^0.03。
- 【对 MAS 故障归因的可借鉴点】相关度：高。
  - 结构上几乎同构：把"最终错误答案/任务描述"当 query 注入对应节点，用 query-dependent GNN 一次前向给轨迹图里每个 step/agent 节点打"责任分"，天然同时给出 agent 级（聚合）与 step 级（节点）归因，且单步多跳（错误沿传播路径回溯）。
  - 可借：关系/节点/查询统一用同一冻结文本编码器初始化到同一空间，使模型对不同 MAS 框架的新角色名、新边类型无需重训（零样本迁移机制）；无参 DistMult 消息函数减少过拟合；BCE + ranking 损失应对"决定性出错 step 极稀疏"；KG 补全式自监督预训练（mask 掉部分消息/边再预测）可利用无标注轨迹（推断）；用偏导数量化推理路径重要性可得到"错误传播路径"的可解释输出。
  - 局限见 (c)：它能零样本是靠 60 个 KG/1400 万三元组的预训练规模。

### #109 GTA-RAG（EMNLP 2026，E 图 RAG）
- 一句话：把图同时当检索环境和过程监督来源：从实体–文档图采样连通文档路径合成多跳轨迹，用部署检索器逐轮验证后，用 GRPO 以轨迹引导奖励训练多轮检索推理。
- 核心机制：实体–文档异构图（文档–实体边、关系边、同义边）+ PPR 图检索（与 Contriever dense 通道取并集）；不放回随机游走采 H 个文档节点，相邻文档间最多经 2 个实体；生成器 LLM 合成多跳问题与逐轮推理轨迹（第 t 轮仅依赖前 t−1 轮已揭示文档）；轨迹验证：用同一检索接口逐轮执行，只保留每轮目标支撑文档都能被检索回来的"可执行轨迹"；奖励：过程项 +0.25/新获取目标文档、未获取 −0.10，终点项答对但证据不完整 +1、答对且证据完整 +2、答错 −1；两阶段：Stage I 在 2000 条验证过的合成轨迹上训 20 步，Stage II 在 10,000 条真实 HotpotQA 上用纯 EM 奖励训 40 步。
- 关键数字：3B/7B 平均 EM/F1 为 44.5/53.6 与 50.5/59.3，超过 Search-R1、RouteRAG；去掉轨迹引导奖励 full-chain 覆盖率 74.1%→58.7%、多跳 F1 降 3.4；target-doc coverage 68.1%→82.3%，complete-trajectory coverage 54.3%→74.1%，平均搜索轮次 2.42 vs 2.48（更少）。简单问答上无普遍优势。
- 【对 MAS 故障归因的可借鉴点】相关度：中高。
  - 与用户数据现状最像：大量程序化合成样本 + 少量真实样本。GTA-RAG 的"合成→验证→过程奖励→真实数据答案级适配"流程可迁移为：故障注入合成（对应合成轨迹）→用回放验证注入的故障确实导致失败（对应"轨迹验证"，缓解不可执行/模板伪迹样本）→带过程奖励训练 → 在少量人工标注上做答案级适配（推断）。
  - "答对但证据链不完整"(+1) vs "答对且证据完整"(+2) 的区分，可类比"agent 猜对 + step 也对"才给满分，抑制只猜 agent 不看 step 的捷径。
  - 局限（原文自述）：依赖图和验证检索器质量，仅在开放域 QA 上验证；过程奖励要求已知"目标证据"，而真实 MAS 失败轨迹没有此类金标（推断）。

### #110 HyperGraphRAG（NeurIPS 2025，E 图 RAG）
- 一句话：首个基于超图的 RAG：用超边一次连接 n 个实体表示 n 元关系事实，并保留每条超边的自然语言描述。
- 核心机制：LLM（GPT-4o-mini）将文档切成独立知识片段，每片段=一条超边 (e_text, e_score∈(0,10])，实体 (name,type,explain,score∈(0,100])；存为实体∪超边的二部图（命题：无损、可增量更新）；双向量库分别索引实体与超边；检索：LLM 抽问题关键实体→实体检索与超边检索（相似度⊙置信度分数，阈值 τ）→双向扩展（实体→所属超边、超边→关联实体）→与 chunk 检索融合生成。参数 k_V=60, τ_V=50；k_H=60, τ_H=5。
- 关键数字：相对 StandardRAG 整体 F1 +7.45、R-S +7.62、G-E +3.69；现有图 RAG 基线（GraphRAG、LightRAG、PathRAG、HippoRAG2）往往不如 StandardRAG；消融（医学域）去掉超边检索 F1 35.4→26.4（降幅最大），去掉实体检索 29.8，去掉 chunk 融合 29.2。
- 【对 MAS 故障归因的可借鉴点】相关度：中。
  - 可直接搬用的数据结构：用"超边节点 + 成员边"的二部图（关联图/Levi 图）表示超图，使任何普通 GNN 都能处理；超边带自然语言文本描述（对应一次讨论/投票的内容摘要）和置信度。
  - 优势（推断）：MAS 日志的超边是现成的，不需要 LLM 抽取，可避开该文的抽取噪声来源；反面：其超图/二元图对比是基于 LLM 抽取的知识超图的 RAG 问答，不是故障归因。

### #111 Hyper-RAG（Nature Communications 2026，E 图 RAG）
- 一句话：超图驱动的 RAG，用超边同时表示低阶（成对）与高阶（多实体）关联，以减少 LLM 在医疗等高风险领域的幻觉。
- 核心机制：1200 token（100 重叠）切块；LLM 抽实体、低阶成对关联、高阶多实体关联，统一存成超边；在线抽实体关键词与关联关键词，分别检索顶点/超边并做一步超图扩散，聚合排序后送 LLM；拼入的先验知识用原始 chunk 文本而非 LLM 合成描述，避免引入新幻觉；Hyper-RAG-Lite 仅实体检索，检索速度翻倍。无训练、无损失。
- 关键数字：NeurologyCrop 上相对直接用 LLM 平均提升 12.3%，相对 GraphRAG/LightRAG 再提升约 6.3%/6.0%；机理指标：关键知识缺失率 KMR −35%，幻觉错误率 HER 0.16→0.08（−50%），错误传播系数 α=HER/KMR 0.59→0.14（−76%）；实体数达 8 时图覆盖率跌至 0%，超图仍保持 50%；最有帮助关联的"度"与完整性显著正相关（r=0.579，p=0.007）。
- 【对 MAS 故障归因的可借鉴点】相关度：低中。(1) "错误传播系数 α"的思路（检索缺失 → 生成放大）可借来设计 MAS 内"早期错误→后续放大"的量化；(2) 多方参与关系中，随参与方增多二元图表达力急剧下降的证据，支持"多 agent 同时讨论/投票用超边"；注意评测问题为 GPT-4o 自动生成、依赖 LLM 评审，证据强度有限（推断）。

### #112 HyperRAG（WWW 2026，E 图 RAG）
- 一句话：面向 n 元超图的 RAG，提出可训练的 HyperRetriever（轻量 MLP 学习 n 元事实上的结构–语义推理）与无训练的 HyperMemory（LLM 参数记忆引导的束搜索）。
- 核心机制：HyperRetriever：主题实体→取其关联超边→把超边内有序实体对枚举为伪二元三元组 (e_h, f^n, e_t)（超边充当关系）；结构邻近编码把 SubGraphRAG 的方向距离编码 DDE 扩展到超边，做 L 轮双向（前向头→尾、反向尾→头）特征传播；特征 x=[φ(q)‖φ(e_h)‖φ(f^n)‖φ(e_t)‖δ] 输入 MLP，二元交叉熵训练（正样本=主题实体到答案最短路径上的三元组，负样本=同一 hop 下相连但不在最短路径上的三元组）；自适应搜索：初始阈值 0.5，保留数<M=50 则每次降 c=0.1，最多 5 次，按超图密度分低/中/高三档处理；生成时 token 预算超边 50%/实体 30%/文本块 20%。HyperMemory：束宽 3、深度 3，LLM 对超边/实体打分，S=S_F·S_E，并做证据充分性检查。
- 关键数字：WikiTopics-CLQA 11 个域平均 MRR 36.94% / Hits@10 43.78%，比最强基线 HyperGraphRAG 平均 +2.95% MRR、+1.23% Hits@10；HyperMemory 始终弱于 HyperRetriever；二元 KG 替代 n 元结构 MRR 36.45%→34.15%、Hits@10 40.59%→36.82%；去掉超边是掉点最严重的消融；开放域结果分化：2Wiki F1 34.06（+11.89% F1），但 HotpotQA（EM 42.5 vs 51.0）、MuSiQue（EM 13.5 vs 22.0）落后于 HyperGraphRAG。
- 【对 MAS 故障归因的可借鉴点】相关度：中高。
  - 本段最有说服力的"可学习结构打分 > 仅靠 LLM 提示在结构上打分"的对照（HyperRetriever vs HyperMemory），与"训 LLM 读轨迹"路线形成方法论对比。
  - 可借：超边展开成伪二元三元组（超边作关系）+ 双向 DDE 结构编码 + 轻量 MLP 打分，参数量小、易做跨框架轻量适配；密度感知的自适应阈值（对应不同框架拓扑稀疏/稠密差异）；理论上超图检索每输出 O(1) vs 二元事件具象化 O(n−k)。
  - 局限：开放域结果不一致，说明超图优势依赖场景。

### #113 Graph Meets LLM 综述（IJCAI Survey Track 2024，D 综述）
- 一句话：按 LLM 在图任务中的角色，把方法分为 Enhancer / Predictor / Alignment 三类（另有 Others）。
- 分类体系：Enhancer（Explanation-based：TAPE、KEA 等；Embedding-based：GALM、SimTeG、OFA 等）；Predictor（Flatten-based：Frozen 如 GPT4Graph、GraphText、NLGraph，Tuning 如 GIMLET、InstructGLM；GNN-based：MolCA、GraphGPT、GraphLLM、DGTL 等）；Alignment（Symmetric：two-tower 对比、GLEM 迭代对齐；Asymmetric：GraphFormer、Patton、GRAD、THLM）。
- 关键观察：Flatten-based predictor 受输入长度限制，只能看到几跳邻居，难捕捉长程依赖且无法解决异配性；GNN-based predictor 更高效，但深层 Transformer 梯度消失使联合训练困难；Alignment 受限于图-文对数据稀缺；未来方向含迁移性、数据泄露与公平基准缺失、可解释性、LLM 表达能力理论分析、LLM 作 Agent。
- 【对 MAS 故障归因的可借鉴点 / 在体系中的位置】相关度：中。现有路线（把轨迹文本喂给 LLM 微调/提示）= Predictor → Flatten-based（Tuning 或 Frozen）；用户的新想法 = Predictor → GNN-based（TEA-GLM / MolCA 式 graph token），或 Predictor→Flatten-based/Tuning 里 GIMLET 式的结构位置编码，或 Alignment→Asymmetric 的 graph-nested（GraphFormer、Patton）≈ HyperBERT 式层内混合；逐步 LLM 判断+GNN 聚合 ≈ Enhancer→Explanation-based（TAPE）。该综述明确指出 Flatten-based 的长度/长程依赖局限，是"区别于训 LLM 读轨迹"的文献支撑。

### #114 LLMs on Graphs 综述（IEEE TKDE 2024，D 综述）
- 一句话：按图—文本关系（纯图 / 文本属性图 / 文本配对图）× LLM 角色（Predictor / Encoder / Aligner）双轴组织。
- 分类体系：文本属性图下，Predictor 按结构注入位置分 Graph as Sequence（规则 InstructGLM/GraphText；GNN 法 GraphGPT、DGTL 等）、Graph-Empowered LLM（每层引入虚拟结构 token + 非对称多头注意力，如 GreaseLM、DRAGON、GraphFormers、Patton、Heterformer、Edgeformers）、Graph-Aware LLM Finetuning；Encoder 为级联（one-step / two-step 训练、数据增强如 TAPE、蒸馏）；Aligner 含 Prediction Alignment（GLEM）与 Latent Space Alignment（对比）。文本配对图以分子为重点（GIMLET、MolCA）。
- 关键观察：线性化破坏图的排列不变性归纳偏置（SELFIES 不在 LLM 预训练语料中，GPT-3.5/4 用 SELFIES 反不如 SMILES）；GNN 侧多停留在 5 层 300 维 GIN 的概念验证规模，可能是表征瓶颈；缺少图感知的参数高效微调；未来方向含更好基准（需覆盖法律/医疗等多领域）、高效图上 LLM、泛化与鲁棒性、LLM 作动态 agent。
- 【对 MAS 故障归因的可借鉴点 / 在体系中的位置】相关度：中。MAS 轨迹 = 文本属性图（消息/step 为带文本节点，交互为边），整条轨迹+失败标签也可视为文本配对图；用户路线落在 Predictor 的 Graph as Sequence（GNN 法）或 Graph-Empowered LLM（层内结构 token，≈ HyperBERT）；现有路线 = Graph as Sequence（规则线性化）。其"线性化破坏排列不变性、长度爆炸"的论述支持动机；"缺少图感知 PEFT"提示 adapter 设计是空白点。

### #115 Graph Foundation Models: Concepts, Opportunities and Challenges（TPAMI 2025，D 综述）
- 一句话：首次正式定义图基础模型（涌现与同质化两大特征），按对 GNN/LLM 的依赖程度分为三类。
- 分类体系：GNN-based；LLM-based（graph-to-token 如 InstructGLM、GIMLET；graph-to-text 如 NLGraph、GPT4Graph）；GNN+LLM-based（GNN-centric：TAPE、GIANT、OFA；Symmetric：GraphFormer、GLEM、G2P2、MolCA；LLM-centric：GraphGPT、TEA-GLM、G-Retriever 等）；复杂图类型中点名超图（PhyGCN、IHP、HyperBERT）。
- 关键观察：GNN+LLM 融合两者优势，但跨模态对齐缺乏统一度量标准；GFM 与语言基础模型的本征差异——图任务数量少但格式各异、不同领域图无共同"词汇表"、GNN 参数量小难以涌现；外在差异——无统一架构、难同质化、跨域泛化弱、涌现能力尚未显现。
- 【对 MAS 故障归因的可借鉴点 / 在体系中的位置】相关度：中。用户路线 ≈ GNN+LLM-based → LLM-centric（TEA-GLM 类），超图部分对应 HyperBERT 所在的复杂图类型。综述给出的"跨域泛化弱、无共同词汇表、涌现未显现"是零样本目标的主要反面论据；同时（推断）MAS 轨迹的节点文本都是自然语言，共享文本空间这一点比一般跨域图更有利。

### #116 PubMed and beyond（eBioMedicine 2024，D 综述）
- 一句话：按五类信息需求场景（循证医学、精准医学/基因组学、语义检索、文献推荐、文献挖掘）整理 30 余款生物医学文献检索工具。
- 分类体系：场景轴而非技术轴；文献挖掘场景用 NER+关系抽取组织成知识图谱做链接预测/文献发现。
- 【对 MAS 故障归因的可借鉴点】相关度：低。仅一条可用信息：综述指出 LLM 在传统 NER/RE 抽取任务上未超越小模型，可作为"不必为抽取结构而依赖大 LLM"的旁证；与图×LLM 方法论基本无关。

### #117 A Survey of Large Language Models for Graphs（KDD 2024 Survey Track，D 综述）
- 一句话：以模型推理/训练流程设计为核心，提出四类分类：GNNs as Prefix、LLMs as Prefix、LLMs-Graphs Integration、LLMs-Only。
- 分类体系：GNNs as Prefix（节点级 tokenization：GraphGPT、HiGPT（异构图）、GIMLET、GraphTranslator、UniGraph；图级：GraphLLM、MolCA、InstructMol、G-Retriever 等）；LLMs as Prefix（Embeddings from LLMs：TAPE、SimTeG、OFA 等；Labels from LLMs：LLM-GNN 等）；Integration（GNN-LLM 对齐 MoMu/G2P2/GLEM；融合共训 GreaseLM、DGTL、GraphAdapter；LLM Agent for Graphs）；LLMs-Only（Tuning-free：NLGraph、GPT4Graph、GraphText；Tuning-required：InstructGLM、LLaGA、ZeroG、GraphWiz 等）。
- 关键观察：GNNs as Prefix 在非文本属性图上的有效性、GNN 与 LLM 最优协同仍未解决；LLMs as Prefix 存在解耦两阶段问题，GNN 性能依赖 LLM 预生成质量；Integration 面临扩展性挑战（多用小 LM 或冻结 LLM）；LLMs-Only 难以把大规模图转成文本 prompt 且缺乏图编码器时难保结构完整性。
- 【对 MAS 故障归因的可借鉴点 / 在体系中的位置】相关度：中。用户路线 = GNNs as Prefix（节点级 tokenization：每个 step 一个 token 供 step 级归因；HiGPT 的异构图 tokenizer 可对应多角色多关系，原文仅点名，未展开细节）+ 可能的 Integration（层内融合）；现有路线 = LLMs-Only（Tuning-free 或 Tuning-required）。可据此把"区别于 LLMs-Only"明确表述为 Prefix 型。

### #118 Graph Foundation Models: Challenges, Methods, and Open Questions（KDD 2025 Tutorial，D 综述，⚠️ 全文暂未公开）
- 一句话：tutorial 论文，系统梳理 GFM 的设计挑战、图模型/语言模型两大家族方法以及分子图与知识图谱应用（以下仅依据官方大纲，未经全文核验）。
- 分类体系：三类异质性挑战——特征异质性、结构异质性（如社交网络的局部依赖/三角闭合 vs 分子图的长程依赖/环）、任务异质性（节点/边/图级各需不同归纳偏置）；预训练三范式（生成式、对比式、多任务）；从迁移性视角审视通用 GFM。
- 【对 MAS 故障归因的可借鉴点 / 在体系中的位置】相关度：中（框架性）。可作为论证框架：不同 MAS 框架间的差异恰好对应三类异质性——文本/角色（特征）、拓扑与步数（结构）、agent 级 vs step 级归因（任务）；"结构异质性需模型结构自适应"支持节点中心/query 条件化而非固定拓扑的设计（推断）。

## 本段综合

### (a) 与该 idea 最相关的论文（按重要性）
1. **#98 TEA-GLM（高）**：唯一一篇完整给出"GNN 表示对齐 LLM token 空间 → 冻结 LLM → 零样本跨数据集/跨任务"的机制与消融（特征级对比对齐是零样本关键；线性投影器+固定 K 个 graph token 满足"轻量 adapter"；指令内带候选答案集）。直接对应需求 (1)(2)(3)。
2. **#108 GFM-RAG（高）**：query-dependent GNN 单步多跳给全部节点打分，且文本统一嵌入使其零微调迁移到七个未见领域；结构上与"给定失败答案，对 step/agent 节点打责任分"同构，同时天然输出 agent 级与 step 级。
3. **#109 GTA-RAG（中高）**：同样是"大量图上程序化合成 + 验证 + 过程奖励 + 少量真实数据适配"，最贴合用户"合成多、人类标注少"的数据现状；其轨迹验证与"证据完整才满分"的奖励设计对抗模板伪迹/猜测捷径。
4. **#99 HyperBERT（中高）**：唯一"超图层混入语言模型"的实现，节点中心上下文超图与同超边邻居为正例的对比损失可用于无标注预训练；但仅有节点分类、无零样本验证。
5. **#96 GIMLET（高，架构备选）**：不另设 GNN，用图最短路距离相对位置偏置 + 解耦注意力掩码把结构写进 LM；指令零样本。
6. **#112 HyperRAG（中高）**：学习式超图结构打分（HyperRetriever）稳定优于纯 LLM 提示打分（HyperMemory），并给出 n 元 vs 二元、超边消融的量化对照与密度感知阈值。
- 次要：#94 TAPE（局部 LLM 判断+GNN 聚合的解耦基线）、#95 MolCA（Q-Former 固定长度压缩）、#105 GraphRAG-R1（RL 与成本感知奖励）、#107（标注流程与 conformal 校准）。

### (b) 可直接搬用的技术组件清单
1. 节点文本编码：冻结句子/BERT 编码器 → 统一特征空间，使不同框架的角色名/消息文本落入同一空间（TEA-GLM、GFM-RAG 共同做法）。
2. 轨迹图 GNN：2 层 GraphSAGE（TEA-GLM）；或 6 层 NBFNet 式 query-dependent GNN + 无参 DistMult 消息 + 关系嵌入由句子编码器初始化（GFM-RAG）。
3. 对齐预训练：实例级 InfoNCE（删边 + 特征掩码两视图）+ 特征级对比（以 LLM token embedding 的 PCA 主成分为坐标轴）（TEA-GLM）；超图版：语义/结构/对齐三项对比，同超边邻居为正例，τ=0.2（HyperBERT）。
4. 图→LLM 接口：线性投影 → K 个 graph token + 含候选答案集的统一指令模板（TEA-GLM）；变长图用 Q-Former（N_q=8）压缩（MolCA）；LoRA 作单模态 adapter（MolCA）。
5. 结构进 LM 内部：图最短路距离 + 边特征的相对位置偏置，图 token 与指令 token 的解耦注意力掩码（GIMLET）；每层 HGNN 分支并行相加（HyperBERT）。
6. 超图表示：超边作为二部图（关联图）里的节点、带文本描述与置信度（HyperGraphRAG）；超边展开为伪二元三元组 (头, 超边, 尾) + 双向 DDE 结构编码 + MLP 打分，密度感知自适应阈值（HyperRAG）。
7. 损失：BCE + ranking（α=0.3）应对正例稀疏（GFM-RAG）；KG 补全式 mask 自监督预训练（GFM-RAG）。
8. 训练策略：合成轨迹 → 回放验证可执行性 → 过程+终点奖励的 GRPO（组内归一化，无 value 网络）→ 真实数据答案级适配（GTA-RAG）；retrieval-masked loss、三阶段训练、成本感知奖励（GraphRAG-R1）。
9. 解耦流水线：LLM 逐节点判断+解释 → 小 LM 编码并冻结 → GNN 聚合，三路特征各训一个 GNN 取平均（TAPE）。
10. 评测与标注：按难度分层和分阶段指标（GraphRAG-Bench）；三层医生评审、Gwet's AC1、planted-error 探针、conformal 校准（#107）。
11. 辅助：熵门控注入（HyRAG）；PPR/阈值剪枝传播作无训练图基线（LinearRAG、GTA-RAG）；DAG 拓扑线性化（LogicRAG）；偏导数路径重要性解释（GFM-RAG）。

### (c) 反面证据 / 风险
- **零样本迁移证据窄**：TEA-GLM 的迁移发生在引文/电商这类"节点是同类短文本"的 TAG 之间，投影器仅在单一数据集上训练；零样本绝对精度不高（Cora 0.202、Children 0.271），OFA 在链接预测上出现负迁移（<0.5），且 OFA 只在主题相近的引文数据间可迁移；TEA-GLM 自己也承认监督性能不及 LLaGA/OFA（拟合更强≠零样本更好）。没有任何一篇在"拓扑/角色/步数差异大"的图域之间验证零样本。综述 #115 也指出跨域泛化弱、涌现尚未显现、对齐缺乏统一度量；#118 的核心挑战正是特征/结构/任务三类异质性。
- **GFM-RAG 的零样本靠规模**：60 个 KG、>1400 万三元组、70 万文档，性能服从 scaling law；MAS 带标注轨迹远小于此量级。它的目标是"与问题语义相关的实体"，而故障归因是因果责任（根因 step 未必与最终答案语义相似）——语义相似度打分可能把"最接近答案的 step"误判为根因（推断）。
- **HyperBERT 证据弱**：仅节点分类、小数据集、直推式、无零样本；绝对精度不高（Cora 64.5%、IMDB 49.7%）；原文自认未验证其他下游任务。
- **图不一定有收益**：GraphRAG-Bench 显示简单事实检索上普通 RAG 持平甚至更优，图冗余成为噪声、prompt 膨胀降低相关性；LinearRAG/MemGraphRAG/HyperGraphRAG 均指出 GraphRAG 常不如朴素 RAG；MemGraphRAG 的初步实验也显示图召回高但相关性低。若 MAS 轨迹较短，长上下文 LLM 直接读可能已够用，图增益只会出现在长链/错误级联等难例（推断）。
- **超图优势证据偏弱或不一致**：HyperRAG 在 HotpotQA、MuSiQue 落后于 HyperGraphRAG；n 元换二元的差距为 MRR 36.45→34.15（约 2 个点量级）；Hyper-RAG 的结论依赖 GPT-4o 生成的问题与 LLM 评审；超图/二元图对比均基于 LLM 抽取的知识图，不是日志天然给定的结构。
- **LLM 可在推理时恢复结构**：LogicRAG 不预建图，仅靠 LLM 动态分解 DAG 就超过预建图方法（2Wiki 64.7 vs HippoRAG2 50.0），意味着"把结构显式写进提示"可能已拿到大部分收益，对"训练图模型"的必要性构成挑战；它同时报告 LLM 过早自信作答。
- **过程奖励不能直接搬**：GraphRAG-R1 的"过程约束"是对检索次数的行为约束（PRA/CAF），并非逐步正确性监督；去掉 CAF 出现检索变多但 F1 下降（reward hacking）。GTA-RAG 的过程奖励依赖已知目标证据（图路径采样得来）；若用注入故障的合成数据做过程监督，会强化模板伪迹，原文也自述依赖图/验证检索器质量，只在开放域 QA 验证，Stage II 仍需 10,000 条真实实例。
- **综述中 LLM-as-predictor / 对齐的局限**：Flatten-based 受输入长度限制、只看到几跳邻居、难处理异配；GNN-based 联合训练困难（深层 Transformer 梯度消失）；对齐方法受图-文对稀缺限制；GNN 侧规模小可能是表征瓶颈（#114）；未来方向还提醒数据泄露与公平基准缺失（#113，TAPE 的 tape-arxiv23 是一种应对）。
- **分子域证据的可迁移性**：GIMLET/MolCA 的收益来自"结构本身就是核心信息"的分子域（单个原子仅 1 个 token）；MAS 轨迹的信息主体是长文本消息，图结构可能只提供有限的增量（推断）。
- **语料局限**：本段无任何关于 agent 轨迹/MAS 日志/因果归因的图建模工作，直接证据缺失，新颖性强但需要自行验证。

### (d) 可能成为直接竞争者 / 必须对比的基线
1. **LLM 展平读轨迹（Flatten-based Predictor，冻结或微调）**：即现有 Who&When / AEGIS / med-SFT 路线（综述 #113、#114 的 Flatten-based）。
2. **"LLM + 显式结构序列化"**：把边、轮次、投票关系以文字/DAG 形式写入提示（GraphText、InstructGLM 式邻居 prompt；LogicRAG 式动态 DAG 线性化）——检验"图模型是否必要"的最强廉价基线。
3. **TEA-GLM 式 graph-token + 冻结 LLM**（本想法的最近邻），以及其消融 w/o GT、w/o FC；原文对比的 GraphGPT、LLaGA、OFA 也应一并作基线。
4. **GIMLET 式结构位置偏置的统一 Transformer**（不另设 GNN）。
5. **HyperBERT 式层内混合** 与 **普通 GNN 替换 HGNN** 的对照（原文该消融 −7.7%）；超图 vs 二元图/二部图展开的对照（HyperRAG 消融）。
6. **GFM-RAG 式 query-dependent GNN 打分器** 与 **HyperRetriever（轻量 MLP + DDE）**：作为"无 LLM 的结构化打分器"基线；HyperMemory 作为"LLM 提示在结构上打分"基线。
7. **TAPE 式"LLM 逐步判断 + GNN 聚合"**。
8. **RL 训练的 agentic 归因器**（GraphRAG-R1 / GTA-RAG 风格，GRPO + 成本/过程奖励）：属于"训练 LLM"路线的强化版，是需要回答"为何不直接用 RL"的竞争者。
9. **无训练图传播基线**：PPR / 阈值剪枝传播（LinearRAG、GTA-RAG 的图检索器）。

### (e) 对五个特别关注点的简答（附加）
- TEA-GLM 机制：特征级对比 + PCA 主成分对齐 + 线性投影成 K 个 token + 冻结 LLM + 指令带候选集；可迁移的是机制，不是结论（迁移仅在同类 TAG 间验证）。
- HyperBERT 层混入：值得借鉴其"节点中心上下文超图 + 逐层相加 + 同超边邻居对比预训练"，但缺零样本与大规模验证。
- GFM-RAG 零样本：关键是"query/节点/关系同空间嵌入 + 无参消息 + 大规模 KG 预训练"，单步多跳打分与归因同构；风险是数据规模与"相关性≠责任"。
- 过程监督奖励：GraphRAG-R1 的过程约束是行为/成本约束，不是 step 正确性监督；GTA-RAG 的"图路径合成+可执行验证+证据覆盖奖励"更接近可迁移，但要求有目标证据金标，需靠注入故障的位置作为金标并做回放验证。
- 综述结论：Flatten 式 LLM-predictor 受长度/长程依赖限制；GNN-LLM 对齐受数据稀缺与缺统一度量限制；GFM 跨域泛化与涌现尚未被证明（#118 为 tutorial 大纲，未经全文核验）。
