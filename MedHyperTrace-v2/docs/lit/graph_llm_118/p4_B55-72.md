### #55 GraphGPT（SIGIR 2024，B）
**一句话**：用"图指令微调"把图结构知识注入冻结的 LLM，目标是零样本跨数据集的节点分类和链接预测。

**核心机制**：
- 图编码器（graph transformer）先与节点文本做对比对齐（text-graph grounding）。
- 图 token 经轻量投影器 f_P（可简化到一层线性）拼进 `<graph_begin><graph_token>_1…_n<graph_end>`，替换指令里的 `<graph>` 占位符。
- 两阶段，LLM 与图编码器全程冻结，只训投影器：
  - 阶段 1 是自监督"图匹配"：给图 token 序列和打乱的节点文本列表，让 LLM 按图 token 顺序重排文本。
  - 阶段 2 是任务指令（节点分类 / 链接预测），用阶段 1 的投影器初始化。
- 用 GPT-3.5 做 CoT 蒸馏，应对类别数变化带来的分布偏移。

**关键数字**：
- Arxiv 训练、PubMed 测试的零样本准确率 0.7011，GCN 为 0.3940（跨数据集后 GNN 崩塌）。
- 103 节点子图只需 750 个图 token，纯文本结构提示需 4649 个 token。
- 仅 stage2（跳过 stage1）易过拟合到特定数据集。
- 去掉图结构（纯 Vicuna）或去掉 LLM 推理（纯图编码器）都明显掉点，尤其零样本。
- 可训练部分约 1.3 亿参数，对比 66 亿，约缩小 50.21 倍。

**【对 MAS 故障归因的可借鉴点】相关度：高**：
- "冻结 LLM + 只训投影器 + `<graph>` 占位符"可直接作为 MAS 轨迹图的注入范式。
- 阶段 1 的"图 token 与文本对应"自监督任务可改造为"轨迹图 token ↔ 消息文本 / 角色 / 步号"的匹配预训练。它不需要故障标签，可用大量未标注或真实 MAS 轨迹，对冲合成数据的模板伪迹。
- 同时提供证据：跳过阶段 1 会掉点或过拟合。
- 局限：零样本是同领域引文图之间的迁移，节点特征统一用 BERT 编码；Cora 70 类时 CoT 变体 0.1813 vs 标准 0.1256，数值仍低。

### #56 LLaGA（ICML 2024，B）
**一句话**：把中心节点邻域重排成"结构感知的节点嵌入序列"，经 MLP 投影器进入冻结 LLM，一个模型统一做节点分类、链接预测、节点描述。

**核心机制**：
- 两种无参数模板：
  - ND（Neighborhood Detail）：固定形状的采样计算树，缺邻居处补 [pad]，层序遍历得到定长序列。
  - HO（Hop-Field Overview）：每跳一个平均聚合的"跳嵌入"。
- 序列拼接计算树邻接的拉普拉斯嵌入以注入位置信息。
- LLM（Vicuna-7B-v1.5-16K）全冻结，唯一可训练的是 MLP 投影器。
- 三个任务统一为聊天 QA 格式，不需要任务头。

**关键数字**：
- 零样本链路预测：Arxiv+Pubmed→Cora 约 87%；Arxiv+Pubmed+Cora→Products（引文→电商，跨域）约 93%，GCN/GraphSAGE 约 57–68%，GraphGPT 约 51%。
- 去掉模板只用中心节点嵌入，性能明显下降，尤其链接预测。
- ND 在需要精细邻居信息的任务（如 Products）更强，HO 在引文网络上靠更广邻域占优。

**【对 MAS 故障归因的可借鉴点】相关度：高**：
- "固定长度、位置可对应的结构序列 + 冻结 LLM + 只训 MLP 投影器"是最简、最易实现的 adapter 基线。
- 模板思想可迁移：把轨迹按"agent 级 → step 级"或"时间窗口 / 邻居"展开成固定形状序列，既保留结构位置，又不依赖框架的拓扑大小。
- 统一 QA 格式、无任务头，利于多任务（agent 定位 + step 定位）共享投影器。
- 多数据集联合训练基本不掉点（GNN 基线反而掉点），为"跨 MAS 框架联合训练"提供弱支持。
- 局限：它是节点中心、采样邻居的设计。MAS 归因需要全局和时序，需要自行改造。上面的跨域成功是二分类链接预测，难度不等同于归因。

### #57 InstructGLM（EACL Findings 2024，B）
**一句话**：完全用自然语言描述图结构（多跳连接、路径、边特征）并对生成式 LLM 做指令微调，不用图编码器。

**核心机制**：
- 提示围绕中心节点，三维组合：最多 3 跳、是否带节点 / 边特征、是否带中间路径。
- 多提示融合训练，链接预测作辅助任务。
- 词表扩展：为每个节点建专属 token，用节点特征初始化 embedding，再加 MLP。
- 超长时借鉴 GraphSAGE 邻居采样。
- 骨干为 Flan-T5 或 Llama-7b（LoRA）。

**关键数字**：
- ogbn-arxiv 上 Llama-7b 达 75.70 ± 0.12，比最强 GNN（DRGAT 74.16）高 1.54%。
- PubMed 仅 60 个训练节点时 Flan-T5-large 达 89.6 ± 0.4，比最强 GNN（SAIL 83.8）高 5.8%。
- 超过 3 跳收益微小甚至有害。
- 作者自述局限：输入长度上限（Flan-T5 为 512，Llama 为 2048 token）限制高阶邻居数量。

**【对 MAS 故障归因的可借鉴点】相关度：中**：
- 它是"图编码 vs 直接文本化"对比里文本化一侧的强证据：纯语言 + SFT 在有监督、同数据集设置下可超过 GNN。这既是借鉴，也是对"必须用图 token"这一假设的挑战。
- 可借鉴的是它的多提示和辅助自监督任务设计。
- 其"为每个节点建专属 token"的做法依赖固定图，不利于跨框架零样本。

### #58 G-Retriever（NeurIPS 2024，B）
**一句话**：面向通用文本属性图的 RAG：检索相关节点和边，用 PCST 取连通子图，再用"图 token + 文本化子图"双通道喂给冻结 LLM 做问答。

**核心机制**：
- 索引、检索、PCST 子图构建、生成四步。
- 检索用 SentenceBert 余弦相似度取 top-k。
- PCST：给 top-k 节点 / 边按排名分奖，边奖用虚拟节点转为标准 PCST，子图规模由边代价 C_e 控制。
- 生成阶段：GNN 子图编码 → 池化 → MLP 投影为软提示；同时把子图展平为文本（CSV 式）。两者拼接后输入冻结 Llama2-7b。
- 只训图编码器和投影层。

**关键数字**：
- 消融（WebQSP）：去掉图编码器 ↓22.51%，去掉文本化图 ↓19.19%，去掉检索 ↓9.43%，去掉投影层 ↓1.11%。
- 幻觉（人工核验 100 条 SceneGraphs 回答）：引用节点有效率 31%→77%，边有效率 12%→76%，完全有效图 8%→62%。
- 效率：WebQSP 的 token 从 100627 降到 610。

**【对 MAS 故障归因的可借鉴点】相关度：高**：
- "图 token + 文本化图"混合注入且互补，是对"图编码 vs 直接文本化"最直接的反证和折中：两者缺一不可。MAS 轨迹的节点文本（具体消息内容）不能丢。
- 长轨迹可借鉴"以问题为条件的子图检索"，只喂候选相关消息和子图。PCST 的"连通性 + 控制规模"适合保持因果链完整。
- 基线 GNN 软提示会幻觉出不存在的节点 / 边，与归因输出必须落在真实 agent / step 上的需求直接相关。
- 局限：检索是静态、基于相似度的。归因的"错误消息"未必与任务问题语义相似，检索可能漏掉真正的错误步。【推断】

### #59 GraphLLM（arXiv 里程碑预印本 2023，B）
**一句话**：用 Graph Transformer 生成"图增强前缀"（graph-enhanced prefix）注入 LLM 每层注意力的 K/V，替代 Graph2Text。

**核心机制**：
- 三步：
  - 节点理解：小型文本 enc-dec，用冻结 LLM embedding 编码节点文本，可学习查询抽取任务相关信息。
  - 结构理解：Graph Transformer，解耦节点信息与结构信息，位置编码用相对随机游走概率（RRWP）。
  - 前缀微调：图表示线性投影成前缀 P，拼到每层注意力的 K、V；LLM 主体冻结，前缀长度 K=5。
- 指令格式为 (Input, Instruction, Response)。

**关键数字**：
- 四个图推理任务平均准确率 98.19%，最佳 Graph2Text 基线 47.35%。
- 上下文长度平均减少 96.45%。
- 把 Graph Transformer 换成 GIN（平均 24.2%）或 GAT（平均 17.3%）后准确率崩塌。
- 45 节点时 gpt-3.5-turbo-16k 的 Graph2Text 准确率跌到 0，GraphLLM 仍为 0.9645。

**【对 MAS 故障归因的可借鉴点】相关度：中**：
- 提供"端到端训练的图模块 + 前缀注入"的另一种注入方式（比只训输入端投影器更强，但需训练图模块，不满足纯轻量 adapter）。
- "解耦节点语义和结构位置"的消融结论说明结构编码器选择会决定成败，可作为设计依据。
- 任务是人工合成的算法型任务（随机图 + gpt-3.5 生成的约 50 token 节点描述），与"合成数据伪迹"风险同构，高准确率不代表真实分布上的泛化。【推断】

### #60 InstructGraph（ACL Findings 2024，B）
**一句话**：用类代码的"结构化格式言语化器"把任意图写成文本，做图中心指令微调（LoRA）加 DPO 偏好对齐，覆盖图推理和图生成。

**核心机制**：
- 图写成 `node_list / edge_list` 或 `entity_list / triple_list`，附属性时用面向对象式（如 `User1.review="..."`），可解析回图。
- 样本形如 (指令, 图, 可选文本段落, 答案)，从 29 个图任务收集约 160 万条指令。
- DPO 负例用 replace / add / remove 构造：错误答案、非事实图、冲突图、缺失图。
- 对"输入图有问题"的情形，正例设为"拒答"。
- 骨干 LLaMA2-7B，LoRA。

**关键数字**：
- InstructGraph-INS 图指令任务平均 79.84%，超 GPT-4 13.08 个百分点；PRE 版在偏好任务再提升约 10 个百分点（平均 82.02%）。
- 代码格式在 PathQSP / WebNLG / Cora / UIE 上全面优于 InstructGLM 的启发式模板。
- 偏好采样中去掉"缺失图"性能下降最大。

**【对 MAS 故障归因的可借鉴点】相关度：高**（作为"文本化"路线的最强对照基线）：
- 一个"统一代码式序列化 + LoRA + DPO"的强文本基线。这一类方法会成为你的新颖性必须对比的对象。
- 可借鉴的技术点：
  - 统一的 JSON / 代码式言语化格式：agent、step、message、vote 都能写成统一 schema。
  - 自动构造"缺失 / 冲突 / 非事实"负例做 DPO，与故障注入的数据构造思路相通。
  - "输入信息有问题则拒答"的训练信号。
- 注意：它没有图 token，也没有冻结 LLM，路线是"训 LLM 读结构化文本"，正是你要区别的对象。

### #61 HiGPT（KDD 2024，B）
**一句话**：面向异构图的图语言模型：用 in-context 异构图分词器（InstructTokenizer）让图编码器不再绑定训练图的 schema，实现跨异构图零样本迁移。

**核心机制**：
- 把 HGT 里类型绑定的参数 Θ=F_Ω(T^{τ(v)})、W^{ρ(e)}=F_Ω(T^{ρ(e)}) 改为由节点 / 边类型的语言增强表示动态生成。
- 类型用自然语言描述（如 "This node represents a movie"），经 Sentence-BERT 编码，每个类型多种描述取平均。
- 轻量文本-图对比对齐。
- 两阶段微调：
  - 阶段 1：异构指令预训练，含"逐序列给出节点类型"和"按图 token 重排同类型文本"两类匹配任务。
  - 阶段 2：监督微调（Vicuna-7B-v1.5）。
- 图 token 离线预计算。
- MoT 指令增强：每条问答生成 7 条增强指令，给 GPT-3.5 提供正确答案作先验。

**关键数字**：
- 零样本（IMDB 训练 → DBLP/ACM 测试，类别数不同）：传统 HGNN 的 AUC 近 0.5，HiGPT Mi-F1 为 0.32–0.51。
- 不做阶段 1 直接下游微调：即使 100 epoch 也失败，无法给出完整准确答案。
- 去掉图 token（w/o HG）：1-shot / 3-shot 差距最大。
- 去掉 MoT 指令增强：性能明显下降。
- 图 in-context 学习：1–2 个带图 token 的示例，1-shot 可超过 60-shot 无 ICL 的模型。

**【对 MAS 故障归因的可借鉴点】相关度：高**（本段唯一直接面向"跨 schema 零样本"的工作）：
- 核心思想可直接迁移：用自然语言描述角色类型和边类型（planner / verifier / voter、"发送消息给 / 投票支持"），再编码成类型表示。不同 MAS 框架的角色名和关系可以通过"类型描述文本"对齐，而不是把 schema 写死进参数。这是应对"不同框架拓扑和角色差异很大"的最相关的现成组件。
- 阶段 1 的类型 / 文本匹配预训练、离线图 token 化、MoT 增强（用已知故障位置作先验生成推理链）都可搬用。
- 图 ICL（少量带图 token 示例）可作为"无梯度的框架适配"手段。
- 局限：实验是 IMDB / DBLP / ACM 三个异构学术 / 影视图，模态单一。节点特征是短文本，MAS 消息是长文本。

### #62 GraphWiz（KDD 2024，B）
**一句话**：构造带显式推理路径的图问题指令集 GraphInstruct（9 类任务），SFT 加 DPO 训练开源 LLM 做图计算问题。

**核心机制**：
- ER 随机图 + NetworkX 程序化出题并算标准答案。
- GPT-4 2-shot CoT 种子 → 训练增强模型做拒绝采样，多样化推理路径。
- 选与"最长正确路径"差异最大的正确路径，去重。
- DPO：以最长正确路径为正例，选"与正例最接近的错误路径"做难负例。
- 输出以 "The answer is …" 结尾。

**关键数字**：
- GraphWiz-DPO（LLaMA 2-7B）9 任务平均准确率 65.00%，GPT-4（2-shot）为 43.81%。
- 最短路任务中节点超过约 60 后准确率几乎归零。
- 增加图-推理路径比（G:R 从 1:1 到 1:5）总体上升，但在 Triangle Sum、Hamilton Path 等复杂任务上反而下降，提示过拟合。

**【对 MAS 故障归因的可借鉴点】相关度：中**：
- 属于"训 LLM 读文本化图并输出推理链"路线，是对照基线。
- 可借鉴："难负例"偏好对的构造（选与正例最接近的错误推理路径）可用于归因 DPO；答案用固定尾缀便于解析。
- 同时给出规模失败条件：图一大，文本枚举式推理就崩。

### #63 Talk like a Graph（ICLR 2024，B）
**一句话**：系统研究把图编码成文本供黑盒 LLM 使用时，编码函数、问题重述和图结构对表现的影响，并发布 GraphQA 基准。

**核心机制**：
- 固定 LLM（PaLM 62B / PaLM 2 各尺寸），只改节点 / 边编码（9 种）、问题重述、提示启发式（zero-shot / zero-cot / few-shot / cot / cot-bag）。
- 7 个基础任务：边存在、节点度、节点数、边数、相连节点、环检测、不连通节点。
- 7 种图生成器（ER / BA / SBM / SFN / 星形 / 路径 / 完全图）。

**关键数字**：
- 选对编码器使 LLM 图推理提升 4.8%–61.8%（依任务而定）。
- Incident 编码（"Node 2 is connected to nodes 0,1,3…"）在多数提示方法下平均排名最优。
- 把图问题重述为应用场景问题几乎全面更优（如边存在 42.8%→60.8%）。
- 环检测在完全图上 91.7%、路径图上仅 5.9%，LLM 的结构先验会左右结果。
- 不连通节点任务几乎完全失败（zero-shot 0.5%）。

**【对 MAS 故障归因的可借鉴点】相关度：中**：
- 对"图编码 vs 文本化"的结论是：文本化不是无损中性接口。序列化方式、命名、场景化问法都显著影响结果，LLM 还带有对图结构的先验偏置。你的文本基线需要做多种序列化的消融。
- 需要全局视角的任务（如不连通）文本化直接失败，支持"需要全局结构的归因不能只靠纯文本邻接"。
- 注意：实验图小（5–20 节点），LLM 不微调，只是提示。

### #64 GraphTranslator（WWW 2024，B）
**一句话**：Translator 把预训练图模型的节点嵌入投影到冻结 LLM 的词嵌入空间，使 LLM 成为图模型的开放式交互接口。

**核心机制**：
- Frozen GM（2 层 GraphSAGE）+ Frozen LLM（ChatGLM2-6B）+ Producer + Translator。
- Producer：因缺图-文本对齐数据，用 LLM 沿"节点自身属性 / 邻居属性 / 两者共性"三个维度做 CoT，生成每个节点嵌入的文本描述，得到对齐对 (z_v, t_v)。
- Translator：BLIP-2 Q-Former 式，M=32 个可学习查询 token，交叉注意力从节点嵌入抽取语言相关特征，线性投影后作为软提示。
- 两阶段：阶段 1 做对比 + 生成 + 匹配三目标，阶段 2 接冻结 LLM 生成式微调。

**关键数字**：
- ArXiv 零样本 Top-1 28.48%，直接喂文本的 LLM 为 17.90%，BERT* 为 14.53%。
- 合法率（Legality Rate）：LLM 基线在淘宝 Lifestage 仅 50–56%，GraphTranslator 为 58.80%–98.97%，LLM 类方法中最高。
- 消融（ArXiv）：仅阶段 1 为 8.22%，仅阶段 2 为 16.94%，两阶段 28.28%。
- 图问答：与直接喂文本的 Vanilla LLM 相当（210 个 A vs 203 个 A）。

**【对 MAS 故障归因的可借鉴点】相关度：高**（针对"LLM 输出不可控"和"缺对齐数据"）：
- 软提示 + 定长压缩相对冗长噪声文本，输出合法率明显更高，可作为"图 token 提升输出可控性"的证据。
- Producer 思路：用 LLM 为节点 / 子图生成摘要作为对齐数据，缓解缺标注。但这些摘要是 LLM 生成的，要警惕引入新的模板伪迹。【推断】
- Q-Former 式固定数量查询 token 天然适配"轨迹长度不一"，输出定长。
- 局限：这里压缩有损。零样本分类提升的同时，原文提到纯文本方法需看到显式词才能判正例，压缩可能丢失具体细节；MAS 归因恰恰依赖消息里的具体错误片段。【推断】

### #65 Actions Speak Louder than Prompts（ICLR Oral 2026，B）
**一句话**：大规模受控评测 LLM 做文本属性图节点分类时的三种交互模式：Prompting、ReAct 式 GraphTool、Graph-as-Code。

**核心机制**：
- 三种交互：
  - 单轮 Prompting（0 / 1 / 2-hop，以及预算版）。
  - GraphTool（think-act-observe，取邻居 ID / 文本 / 标签）及 GraphTool+（批量 k 跳）。
  - Graph-as-Code：把图存成按 node_id 索引的表（features / neighbors / label），LLM 迭代生成并执行代码。
- 14 个数据集，覆盖同配 / 异配、长 / 短文本，主模型 o4-mini，5 个种子。
- 通过删边 / 截断特征 / 移除标签画二维依赖热力图。

**关键数字**：
- Graph-as-Code 总体最强，尤其长文本或高度图上；2-hop prompt 在 reddit / photo / wiki-cs 等上多次触发 TokenLimit。
- wiki-cs 上 2-hop prompt 单查询约 1,157,000 token，Graph-as-Code 约 57,100。
- 随机打乱邻接矩阵后所有结构感知方法显著下降，证明优势来自真实利用结构。
- 与监督架构对比：混合 LLM+GNN（LLaGA、TAPE 等）总体最优；零样本 Graph-as-Code 在多数长文本集上接近或持平 GNN（computer 上 86.20 vs GCN 71.44 / GAT 83.39）。
- 所有交互模式在异配图上依然有效（cornell 上 Graph-as-Code 达 92.70%）。

**【对 MAS 故障归因的可借鉴点】相关度：高**（既是证据，也是竞争者）：
- 提供"不训练、LLM 靠工具 / 代码按需读取图结构"的免训练基线，对长文本节点、高度节点更有优势，直接威胁"必须训图大模型"的动机。MAS 轨迹正是长文本消息，Prompting 容易爆 token。
- "信息依赖"消融方法（独立删边 / 删特征 / 删标签）可直接借用，用于证明模型确实用到了轨迹结构，而不是只读文本。
- 随机打乱邻接矩阵对照可用来验证"结构真的被使用"。
- 局限：任务是节点分类，主模型 o4-mini 等推理模型，非轻量 adapter。

### #66 Message Tuning / MTG（ICML 2026，B）
**一句话**：给 GNN 型图基础模型每层注入少量可学习"消息原型"以动态改造消息融合，并用棱镜空间理论证明其适应能力可超过图提示调优。

**核心机制**：
- 每层 m 个可学习原型 M，融合 F = H + Softmax(H·Wp)·M，预训练权重冻结。

**关键数字**：

- 作者自述局限：需要白盒逐层访问，不适用于黑盒 LLM / API 型图基础模型。

**【对 MAS 故障归因的可借鉴点】相关度：低**：作用对象是 GNN 主干，不涉及 LLM；仅在"轻量冻结主干 + 少量参数适配"上有弱呼应。

### #67 MSGCOT（WWW 2026，B）

**核心机制**：

### #69 EstGraph（ACL 主会 2026，B）

### #71 Reason-Align-Respond / RAR（TPAMI 2026，B）
**一句话**：Reasoner 生成自然语言推理链，Aligner 把它对齐到 KG 上真实存在的知识路径，Responser 综合作答；EM 联合训练。

- 局限（原文）：在高度专业化 KG（如医疗）上的泛化有待提升。

**【对 MAS 故障归因的可借鉴点】相关度：中**（针对"输出不可控"）：
- 约束解码（强制输出落在真实存在的元素上）可直接迁移为"只能输出轨迹中真实存在的 (agent, step)"。
- "先推理、再对齐到图上真实元素、再作答"的三段式可用于归因：先生成失败原因链，再对齐到具体节点。

## 本段综合

### (a) 与该 idea 最相关的论文（按重要性）
1. **#55 GraphGPT**：冻结 LLM + `<graph>` 占位符 + 只训投影器 + 自监督"图 token ↔ 文本匹配"阶段，是目标范式的原型；同时给出"没有阶段 1 就过拟合"的失败证据。
2. **#56 LLaGA**：最简、定长、无参数的结构序列模板 + MLP 投影器 + 统一 QA 格式；多数据集联合训练不掉点，是最直接的轻量 adapter 基线。
3. **#61 HiGPT**：唯一正面处理"schema / 类型异构的零样本迁移"，用自然语言类型描述生成类型相关参数，最贴近"不同 MAS 框架角色和拓扑不同"的痛点。
4. **#58 G-Retriever**：图 token + 文本化子图的双通道，消融量化了两者互补（去图编码器 ↓22.51%，去文本化图 ↓19.19%）；带 PCST 子图检索和幻觉量化。
5. **#64 GraphTranslator**：Q-Former 式定长软提示，输出合法率更高（针对 LLM 输出不可控），并提供 LLM 生成对齐文本的做法（缓解缺人工标注）。
6. **#65 Actions Speak Louder than Prompts**：既是方法论工具（信息依赖消融、打乱邻接对照），也是最强的免训练竞争者，需要正面回应。
- 次要但有用：#60 InstructGraph（强文本基线 + DPO 负例构造）、#71 RAR（约束解码）、#63 Talk like a Graph（文本编码敏感性）。

### (b) 可直接搬用的技术组件清单
- **注入范式**：冻结 LLM，仅训投影器（线性或 MLP），图 token 以 `<graph_begin>…<graph_end>` 或 `<node sequence>` 占位符替换进指令（#55 #56 #70）。
- **图 token 的构造**：
  - 固定形状的采样计算树 + [pad] + 拉普拉斯位置嵌入（#56）。
  - Q-Former 式固定数量可学习查询 token，对输入长度不敏感（#64）。
  - 前缀注入到每层 K/V（#59，需训图模块）。
- **预训练 / 对齐任务**：
  - 图 token ↔ 文本匹配（打乱节点文本并让 LLM 按图 token 重排，#55 #61 #70）。
  - 类型匹配（逐序列给出节点类型，#61）。
  - 图-文本对比对齐（#55 #61 #64 #70）。
  - 节点描述任务（#56）。
- **跨 schema 适配**：用自然语言描述节点 / 边类型，Sentence-BERT 编码，多种描述取平均，驱动类型相关参数（#61）。
- **图 + 文本混合输入**：图 token 与文本化子图拼接（#58）。
- **子图控制**：以查询为条件的 PCST 检索，控制规模并保持连通（#58）。
- **指令格式**：
  - 统一 QA 聊天格式，无任务头（#56）。
  - (指令, 图, 文本段落, 答案) 元组加类代码言语化（#60）。
  - 答案固定尾缀便于解析（#62）。
  - 图 ICL 示例无梯度适配（#61）。
- **输出控制**：约束解码，限制输出落在真实存在的元素上（#71）；拒答训练信号（#60）；结构化推理链标签（#71）。
- **训练数据策略**：用已知答案作先验让强 LLM 生成多样化推理指令（#61 MoT）；replace / add / remove 构造 DPO 负例（#60）；难负例选"与正例最接近的错误推理路径"（#62）。
- **评估方法**：删边 / 截断特征 / 移除标签的信息依赖消融，以及打乱邻接矩阵对照（#65）；人工核验引用节点 / 边有效率（#58）。
- **去伪迹**：节点名随机大数匿名化（#69）；剥离框架 / 模板因子只保留不变量子（#70，类比）。

### (c) 对该 idea 的反面证据 / 风险
1. **"图编码 vs 文本化"没有单一赢家**。
   - 文本化一侧：#57 InstructGLM 纯语言 + SFT 在有监督设置下超过 GNN；#60 代码式言语化 + LoRA + DPO 平均 79.84%，超 GPT-4 13.08 个百分点。
   - 图编码一侧：#59 在合成算法任务上大幅领先 Graph2Text（98.19% vs 47.35%）；#55 一个 103 节点子图图 token 750 vs 文本 4649。
   - 混合一侧：#58 显示两者互补，任一去掉都明显掉点。
   - 结论：如果只用图 token，可能不如图 token + 文本；但要强调"只用图 token"的优势就必须证明它不丢细节。
2. **免训练的强竞争者**：#65 的 Graph-as-Code 在长文本、高度节点上优于 Prompting，零样本在多数长文本集上接近或持平 GNN。MAS 轨迹正是长文本。
3. **压缩有损**：图 token 压缩节点文本。#64 提到纯文本需看到显式词才判正例，说明压缩与显式信息之间存在取舍；MAS 归因依赖消息里的具体错误片段，因此有丢失细节的风险。【推断】
4. **零样本证据偏弱、偏窄**：
   - #55 #56 #61 的"零样本"都在同类图之间（引文 / 学术 / 影视）、节点特征统一用 BERT / SBERT、任务为节点分类或二分类链接预测。#61 的零样本 Mi-F1 只有 0.32–0.51；#55 在 70 类 Cora 上（原文 CoT 蒸馏对比处给出，未明确是否零样本）CoT 变体仅 0.1813。
   - 没有任何一篇在结构大不相同的图（不同拓扑 / 步数）之间迁移。
   - #61 指出 ACM 在阶段 1 中编码不足，说明跨集迁移依赖预训练覆盖。
5. **失败条件（原文给出）**：
   - 跳过阶段 1 自监督对齐：#55 过拟合，#61 即使 100 epoch 也失败。
   - 类别数变化：#55 需要 CoT 蒸馏补偿。
   - 参数绑定 schema：#61 指出传统 HGNN 的 AUC 近 0.5。
   - 结构编码器选择：#59 把 Graph Transformer 换成 GIN / GAT 后平均掉到 24.2% / 17.3%。
   - 规模：#62 最短路节点超过约 60 后准确率几乎归零；#63 不连通节点几乎完全失败。
6. **合成数据风险与本段合成任务同构**：#59 的任务是随机图加 gpt-3.5 生成的节点描述；#62 是 ER 图程序化出题。这些高准确率不能证明在真实、非模板化数据上成立。【推断】
7. **形态不匹配**：
   - 本段方法多为节点中心、采样邻域；MAS 归因是整条轨迹上的 agent / step 定位，需要全局视角和时间顺序。
   - 本段全文无超图、时序和 MAS 处理。超图建模（投票 / 共识作超边）在本段中没有任何先例可借。
8. **输出不可控依然存在**：#58 的软提示基线引用的节点 / 边有效率只有 31% / 12%；#71 无约束解码时即使答案正确也有 44% 路径幻觉。归因输出需要受约束解码或检索式候选，否则会输出不存在的 agent / step。
9. **训练成本**：#57 InstructGLM 在 ogbn-arxiv 上 Llama-7b 每 epoch 约 6 小时；#71 的 EM 训练较重。这些与"最多轻量 adapter"的要求不一致，只能当作对照。

### (d) 可能成为直接竞争者 / 必须对比的基线
- **文本化 + 微调 LLM（你现有路线的图中心版本）**：#60 InstructGraph（代码式言语化 + LoRA + DPO）、#57 InstructGLM（纯自然语言结构描述）、#62 GraphWiz（SFT + 难负例 DPO）。它们等价于 Who&When / AEGIS / med-SFT 路线，是证明"图 token 有增益"的基线。
- **图 token + 冻结 LLM + 只训投影器**：#55 GraphGPT、#56 LLaGA 作为架构基线，#64 GraphTranslator 作为 Q-Former 式对照。你的方法需要证明超边 / 轨迹结构编码比它们的通用节点中心编码更适合。
