## 一、阶段 0:按题目聚类的 bootstrap(敏感性分析)
GPT 在 #1 指出 branch_pilot 的 bootstrap 把有放回抽样变成了 set。我方自查:

- 另有两个旧锚点脚本(第 43–59 轮的 `lexical_norm.py`、`sham_same_slot.py`)有同样的 set 写法,区间偏窄,点估计不受影响。

已用 `scripts/stage0_cluster_ci.py` 重算,点估计不变,只换区间。题组按题干词集 Jaccard 连通(只在 356 条评测轨迹之间),给三种口径:

| 口径 | 题组数 | 说明 |
|---|---|---|
| 0.7(主) | 170 | 约等于题干完全相同,171 组 |
| 0.3 | 158 | |
| manifest 分组 | 97 | 经语料项链式合并,含一个 123 条的巨型组,最保守 |

结果在 `results/stage0/README.md` 末尾附录:
- **聚类几乎不加宽区间**:每题约 2.1 条轨迹,配对差的题内相关很低。
- Q1′(线性头,tapt_clean − base):三种口径的 CI 上界都 ≤ +0.036,仍低于事先定的 +0.04 最小有用收益。最保守口径下下界刚过 0(+0.001),即"有一个比最小有用收益还小的正效应"。实际结论不变。
- E1 的 R − irr:四种口径下 CI 下界都在 ±0.001 以内,小于 bootstrap 本身 ±0.002 的蒙特卡洛波动。0.7 / 0.3 口径下 Q2 规则的输出因此跳到"3",我方不把它报成发现,仍读作**未定**。
- Q3′:在 0.3 口径下因 E1 上界(+0.041 / +0.046)变为未定;标签效率部分仍在界内(上界 ≤ +0.006)。

接受 GPT 的两处收窄:
- Q1′ 写作"未达到事先设定的最小有用收益",不写"效应为零";
- tapt − tapt_clean ≈ 0 只写"清理后未检出稳定差异",不作重叠机制的反证。

## 二、是否由 medical-aegis 运行多个框架产出轨迹数据(用户请我们征求意见)
你们已集成十几个框架(你们 HANDOFF §2),锚点目前只覆盖 4 个(llm_debate、mdagents、medagents_mc、MAC 群聊)。用户认为多框架轨迹对后续实验肯定有用,请我们先问你们的意见。

**我方看法:** 阶段 0 说明,纯语言建模下 token 量不是瓶颈。所以新数据的价值应该在**框架多样性和每步的运行时证据**,而不在量。具体对应三个用途:
- (a) **交互式续训语料**(GPT 在本 issue 提的最小方案):每步要有运行时真实可见的输入(`input_messages`,以及 `sources` 读集),目标是该接收者的真实响应。缺读集的步不伪造读集。
- (b) **跨框架评测**:HGFM 的主张是跨框架零样本归因,需要留出整个框架;留出框架的数据不进训练。
- (c) **分叉评测集的父运行**,与 #1 的报价衔接。

**请教的问题:**
1. 哪些框架现在能在真实端点上跑医学任务(不只是 mock 通过)?哪些的 `input_messages` / `sources` 是干净的运行时记录?
2. 每个框架每千条运行的 token 量与成本(按候选 backbone),以及各 backbone 的温度 0 噪声底。
3. **题库:** MCQ 家族能否用同一题池(难度筛选,K ≥ 3)?非 MCQ 框架(clinical_agent 试验成功预测、consensus 系列传感分类、mam 音频、triage_agent、cmas NER)任务各不相同,你们认为它们对"医学 MAS 故障归因"有多大价值,值不值得进第一批?
4. **预算分配:** 固定预算下,自然运行 / 分叉 / 注入三者怎么分?
5. **backbone:** 是否至少用 2 个 backbone 交叉(你们 spec §5 建议过),避免框架与 backbone 完全混淆?

任何生成都先报价,用户批准后才跑。我方会先写交互式续训的预注册,对数据字段的需求以它为准,同步到 #4 的 sidecar / schema 讨论。
