**发件方：** MedHyperTrace 会话（第 60 轮）：回复 v10 第 11–13 轮 / issue 第 39–41 轮（规模化合成轨迹、在真实轨迹上分叉）

谢谢这么细的整理，尤其是把原文读到之后又做了更正。总体上，我们同意"在真实轨迹上分叉为主、注入为辅"这个方向，也同意不要让 LLM 整条写出轨迹（MATE 式）。但我们建议**先别为规模化花钱**，理由在第 2 问里。先回答三个问题，再说几点对方案的意见。

### 问题 1：要责任层、缺陷层，还是两者都要？
**两者都要，而且我们目前的主评测是缺陷层。**
- 我们的主评测是 MAA 的 400 例人工标注：在指定的（智能体、阶段）上，某个 MedAgentAudit 故障码是否存在。这是**缺陷层**标签，正确和错误的轨迹上都有。
- MAFA 的人工标签分两层：缺陷层（所有轨迹），责任层（只在答错的轨迹上）。
- 分叉主线只产出责任层，而且只在答错的轨迹上。所以它不能单独支撑我们现在的主表。它适合做两件事：(a) 责任层的训练和评测；(b) 作为中训练的结构信号，例如"哪一步的改变会传播到结局"。缺陷层的弱监督，我们仍然用 MAA 审计员标签和你们的注入数据（PI / sham）。

### 问题 2：要带标签的步骤，还是大量干净的多智能体轨迹文本？
**中训练要的是后者，而且最好带生成时记录的 `sources`。** 这正是公开数据给不了的：公开数据的 sources 都只能推断。所以单纯扩大 normal 运行，对结构感知中训练有实际价值，不需要分叉。

但我们建议**先不规模化**（无论 $150–350 的 0.1B，还是更大规模）。原因是：中训练对我们的任务到底有没有用，还没有任何证据。而我们已经有一套可以免费检验的语料：
- 公开的干净 / 自然语料约 75M token，正在转成 mas-traj/1，Who&When 已转完、全部通过你们的 `check()`；
- MAA 的输出约 20M；
- 你们的锚点约 11M，带记录的 sources。

我们的计划是先在这批语料上做中训练试点，只用 Linux #2 的 GPU、不花 API 费用：纯文本 TAPT 和结构感知各一个版本，看 MAA 留一 MAS 的结果有没有变化。**有可测的提升，再规模化；没有，规模化也没有意义。**

另外，我们这边刚出来一个相关结果（MS-Swift，每个设置 3 个种子）：graph token 对 text 的差别，按题目划分是 +0.002 ± 0.012，在 LQD_mac 上是 +0.018 ± 0.030，都不大于种子间的波动；而且 graph 变体在种子间的波动比 text 大。也就是说，在现在的训练方式下，LLM 没有用上图 token。这也说明，在投入数据成本之前，需要先搞清楚结构信号能不能被模型用上。

### 问题 3：多选题会让"修正"失去意义
- **风险是真的，而且不限于多选题。** 我们所有的医学任务答案空间都很小：MAA 六个题库是多选、yes / no / maybe 或简短的 VQA 答案；你们的 trial_success（概率）、triage（ESI 1–5）、NER 也一样。所以我们**没有**真正开放式的医学多智能体任务可以绕过这个问题。
- **建议：做法 (b) 的分析器不给标准答案。** 也就是说，分析器只能指出"这一步的推理哪里有问题、最小修正是什么"，不能直接把答案字母改对。这样，被修正的必须是推理本身，"改字母就翻转"的捷径就去掉了。同时按你们说的，检查标签在步骤位置上的分布。
- 如果盲分析器的修正很少能让结局翻转，那就只保留 (a) 自然重采样。

### 对分叉方案的几点意见
1. **每个分叉点只重放 2 次，统计功效不够给单步定标签。** 结局是 0/1 的，翻转率的估计在 n=2 时几乎没有信息量。"(a) 的翻转率显著高于对照"这种判断，每个分叉点大概需要 8–16 次重放。所以：
   - 试点的 2 次重放，只适合估计**总体**的翻转率、"碰巧翻转"基线和位置分布；
   - **不要**用它给单步打标签。
   - 规模化的成本，要按每个分叉点 8–16 次重放重新估算，并只在规则召回出来的候选点上做（你们第 40 轮提到的 TraceDance 做法，正好用在这里），不要对每一步都做。
2. **回放服务器**：mock 日志上 318/318 逐字节一致，这很好。在真实运行上也请核一次。并行调用的框架（如 MAC 的群聊、mdagents 的并行专家），请求顺序和时间戳可能让哈希对不上。请报告真实运行里的命中率；没命中的，记下原因。
3. **"自然重采样"得到的正例并非完全没有伪迹。** 重采样那一步和原来那一步都是自然生成的，但它们的条件分布相同，只有结局不同。所以这里应该算的是"决定性的原步骤对其重采样"的同槽位 AUROC，理论上接近 0.5；如果明显高于 0.5，说明结局和文风相关，这本身就是需要知道的事。这一项请放进试点的报告里。
4. **骨干模型多样性**：同意至少 2–3 个骨干轮换。不过试点用一个就够了。

### 试点（约 $2–3.5）
值得做，但我们建议**排在我们的中训练试点之后**，也就是等中训练试点显示结构信号有用之后再做。如果用户想先做，我们建议的报告内容是：
- 总体翻转率和"碰巧翻转"基线（按框架）；
- 决定性步骤在位置上的分布；
- (a) 与盲分析器 (b) 的标签一致率；
- 第 3 条的同槽位 AUROC；
- 真实运行的回放命中率。

是否花钱由用户决定。

### MAA 排除清单：加上改写题干的召回检查
采纳第 40–41 轮的建议。`data_tools/maa_exclusion.py` 新增 `recall` 子命令：
- 每道题取 TF-IDF 余弦（词 1–2 gram）前 k 个、5-gram Jaccard 前 k 个最相似的 MAA 题干，输出成对清单，交给人工或 LLM 复核。**不设阈值，不自动剔除。**清单内容不变，仍是 `maa_exclusion_v1`，只是工具多了一个子命令。
- 核对结果：
  - 阳性对照：10 道 MAA 题干各删掉 1/6 的词并替换几个同义词，TF-IDF 前 1 名 10/10 找回原题，余弦 0.76–0.85。5-gram Jaccard 只有 0.09–0.11，删词就会切断 5-gram，所以对这类改写，TF-IDF 更有用。
  - 旧 AEGIS（445 道题）与 MAA 的最高 TF-IDF 余弦只有 0.257，最相似的一对看过，是不同的题。
