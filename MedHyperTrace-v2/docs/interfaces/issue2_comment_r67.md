### 1. OAT 和我们的中训练可以直接串联
看了 OAT 的 `extract_states.py` 和 README:它的步骤表示是**代理 LLM(Qwen3.5-27B)读轨迹时的末层隐状态均值**,不是 agent 自己的隐状态;CDE 只在成功轨迹上训练,推理时用偏离程度打分。
- 所以"无监督(OAT)"和"自监督(我们的 TAPT / SAMT)"不是互斥的范式。OAT 也是自监督,只是另外用了"成功"这个结局标签来挑训练数据,读出时也不微调。两者可以组成课程:**通用轨迹 LM(TAPT)→ 结构 / 交互(SAMT v2)→ 成功流阶段(OAT 头)→ 可选的轻量适配**。中训练改变的,正是 OAT 的代理 LLM。
- 关于成本:OAT 的 200–5000× 不含隐状态提取(GPT 已指出)。在我们的设定里,代理 LLM 本来就要读整条轨迹,所以把这一项算进端到端成本。
- 关于评测:OAT 的 AUROC 是把所有轨迹的步骤分数池化后计算的,会受不同运行之间分数尺度的影响。我们的预注册把**轨迹内**指标(Acc@1、Hit@3、错误步在本轨迹内的 rank-AUROC)定为主指标,池化 AUROC 只作为与论文可比的次要指标。

### 2. G 节:实际核对后,新增的自然 MAS 轨迹很少
- **agent-scaling(NMI,G4):** 仓库只有 10 条示例轨迹(约 160 KB),没有完整发布轨迹。
- **AgentFail(B9,G1):** README 写"dataset coming soon",但仓库里已有约 23 MB 的 Dify / Coze / n8n **节点级输入输出日志**和标签,也就是带实际输入。这一项值得接入,规模待统计。
- **OAT 的 MCP-Atlas(G1):** 198 条(其中 191 条可用:103 成功、88 失败),Qwen3.5-27B **单 agent** 工具调用,平均 7 步。
- 其余条目要么和我们已转换的数据重复(Who&When、TraceElephant、AgentRx、CORRECT-Error),要么诊断的是微服务 / 代码这类非 agent 系统。
- 而且我方已转换但还没用的干净公开语料约 75M token,TAPT 只用了 24.5M,结果是阴性。**token 数量不是现在的瓶颈。**manifest v1 仍然值得做,主要用来去重和划定评测留出集。

### 3. 合成数据要分两种
- **真实运行 MAS 框架产生的自然轨迹**(medical-aegis 现在的做法):带运行时记录的输入和来源,正好补上 B2 / B3 的数据缺口(现在高可信的只有锚点约 900 条运行)。按你们实测的单价(每条 $0.0017–0.0028、约 4.2k token),1 万条约 $20–30。是否扩大,由用户在 E1 结果出来后定。
- **LLM 直接写的轨迹文本**:不建议作主语料。注入数据的格式 / 措辞签名问题我们查了二十多轮(同槽位 AUROC 0.86–0.95);生成的轨迹里也没有真实的"谁看到了什么"。

### 4. 评测
- MAA 一直是我方缺陷层的主评测(400 个人工实例),继续使用。它没有责任层标签。
- 责任层:Who&When 184 + TraceElephant groupchat 176(从未进中训练语料)作外部评测;医学分叉点只描述性报告,检验力不足。分叉标签是我们最信得过的合成标签,注入标签不作评测真值。
- **防止挑评测:**指标和判定规则在跑之前已提交:`MedHyperTrace-v2/docs/design/E1-E3_prereg_v1.md`(提交 `33dd4f7`)。

### 6. 对 Muse 文档的两点补充
- C12(归因基准可被简单预测器利用)和 C13(线性探针显示模型"知道但不说")对我们的设计最有用:前者要求必报平凡基线;后者支持用中训练后模型的隐状态做读出,而不是靠生成。
- G 节的"16 项"是论文数,不是独立数据集数;实际可用的新增量要以逐项下载、统计后的数字为准。
