## 一、三项核查

### 1. TracerTraj 与 WW / TEgc 有任务重叠(GPT 的担心成立,我方第 71 轮"无重叠"是错的)
- 第 71 轮只查了**精确**的题目匹配和 ≥200 字符的步骤文本匹配,结果都是 0。
- 改用词集 Jaccard 后:358 条留出轨迹里,有 **110 条**(WW 47、TEgc 59)的题目在 TracerTraj 训练文件里有近似重复(≥0.3)。阈值往上看:≥0.5 有 106 条,≥0.7 有 51 条,≥0.9 有 6 条。
- 这些是同一道 GAIA 题,TracerTraj 只是在前面加了一句 "Please answer in a concise format..."。
- 轨迹和标签都不同(换了 MAS,换成注入错误),但任务本身是重叠的。
- **去掉这 110 条后重算 E4(n = 248):**
  - BEFT 控制后 rank-AUROC:base 0.640、tapt 0.648,比随机高 +0.14 [+0.10, +0.18];

  - 也就是说,重叠**没有**抬高迁移结果,E4 的两个结论都不变:有监督标签能迁移,中训练不带来提升。
- 今后外部数据去重一律按"题干归一化 + Jaccard ≥ 0.3,按题目分组",写进规范。

**更正我方第 68 轮的说法。** 当时说"E1 的增益全部来自步长",这个结论过强。GPT 和 Muse 对线性残差化的批评是对的。准确的表述是:

## 二、对几处分歧的立场
- **零干预臂:** 同意 GPT 的更正。末步直接产出答案,D(t) 为空并不等于"无作用";负对照应按 GPT 给的执行契约来定(没有任何下游读取、final / verifier 不读取、无副作用),并与"重复续写对照"分开统计。
- **约束的操作定义:** 同意 Muse 要求写成可检验的定义;GPT 列的四条(更新共享主干、多目标、产出可复用 checkpoint、与同等适配预算的基座比较零样本 / 少标签 / 满标注)可以直接作为定义。
- **停止规则:** 我同意 GPT 不用拍脑袋的阈值,但阈值应该由实测检验力来定,而不是取消。
  - 本评测(n = 356)上,配对 rank-AUROC 差的 95% CI 半宽实测约 0.02–0.03(E1、E4 各项),最小可检测效应约 0.04;匹配配对的半宽约 0.04–0.065。
  - 我建议的写法是"无效界":某个配方在控制后 / 匹配后的差的 CI **上界** < +0.04,就停掉这个配方。这能检验,也不终止整个方向。
- **标签效率曲线:** 同意列为共同主指标,并且现在就能做,零 API:用 E4 现成的管线,TracerTraj 取 100 / 500 / 全量标签,比较 base vs tapt。冻结探针几分钟一组;BEFT 全量约 3 小时(4 卡),小标签量更快。
- **负对照中训练(打乱 / 无关文本):** 第一节第 2 点之后,我改为支持 Muse,把它前移。E1 的 OAT 增益在长度匹配下还剩 +0.05,只有负对照能区分"学到了轨迹知识"和"任何持续预训练都会造成的表示漂移"。成本是 S / R 同规模约 1 小时训练 + 35 分钟 OAT,不调用 API。我同意 GPT 的意见,把它当机制消融,不当二元开关。
- **图信息探针:** 同意先做接口诊断(GPT 的两层设计),不作为 SAMT v2 的准入门槛。

## 三、我方的新见解
1. **我们所有读出器都看不到"之后发生了什么"。**
   - OAT、冻结探针、BEFT 用的都是因果 LM 中、该步 token 上的末层隐状态均值,每个步骤的表示只编码它的前缀。
   - 离线归因最有用的证据——后面的矛盾、纠错、verifier 输出——这些表示根本看不到。GPT 指出离线任务允许使用下游证据,这一点在我们的实现里恰恰是缺的。AgenTracer 一类生成式判定器能读完整轨迹。
   - 这可能部分解释两件事:我们的 WW 步骤级准确率只有 0.21–0.27,AgenTracer 约 32–36%;以及上面"无标签读出有一点、有监督没有"的不对称。
   - 改法:在步骤表示之上加一个**双向**的轻量聚合器(跨步骤的小 Transformer),或者做第二遍"带后文"的编码。这两种做法都和中训练兼容。
2. **零 API 的中训练目标候选:替换步检测(类似 ELECTRA 的 RTD)。**
   - 做法:把一条自然轨迹里的某一步,换成同题另一次运行(锚点 K = 3、公开数据里的多次运行)里**同位置、长度相近**的步骤,让模型找出被换的那一步。
   - 标签按构造得到,长度按构造匹配,所以从源头上排除了步长捷径;语料可以覆盖全部约 75M token,不需要任何付费调用。
   - 它介于"自然轨迹语言建模"和"付费分叉对"之间:学的是轨迹内的一致性,而不是因果责任。所以它只能作为台阶,必须用 E4 的有监督迁移 + 标签效率曲线来检验,不能单独当证据。
   - 它和超图主线直接相关:跨运行换步会破坏"谁读了谁"的依赖——后续步骤引用了被换步里并不存在的内容。这恰好是超图读集结构应当帮得上忙的任务,可以拿来检验 SAMT v2"有图 vs 无图"的价值,而不必先等分叉数据。
3. **基准审计(同意 Muse §2(1)):** WW / TEgc / TracerTraj 的长度、位置基线我方已有,并已补上重叠检查;MAA、MAST-Data、AgentRx 等可以离线补齐,做成一张表。
