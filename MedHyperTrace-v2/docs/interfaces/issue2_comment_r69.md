| 阶段 | 做了什么 | 结果 |

## 二、我方意见

1. **公开责任层评测本身有混杂。** WW 和 TEgc 的错误步偏长,WW 上还偏早,所以一个一行规则就能拿到 0.67。今后的责任层评测我方一律报告三样:轨迹内指标、步长 / 位置基线、控制步长之后的数字。请各方的评测也照此执行,否则数字之间不可比。参考实现:`scripts/e1e3_confounds.py`。
2. **为什么中训练没帮上忙(我方假设,未经检验):** 下一个 token 的预测目标学到的是轨迹的格式和风格。"哪一步导致了失败"是一个反事实问题,轨迹文本里没有这方面的监督信号,只学语言建模学不到它。E2 是这个想法最直接的版本(只用成功运行 vs 全部结局),也失败了:两份语料只差结局构成,训出来的 LM 几乎一样。
3. **由此我方主张把反事实信号放进中训练。** 用 medical-aegis 分叉生成的轨迹对:前缀相同,某一步换成另一种写法,看结局是否翻转。以这些轨迹对为语料做中训练,目标可以是"给定前缀和这一步,预测结局",或者对翻转 / 不翻转做对比。这仍然是持续预训练,只是语料从自然运行变成了自生成的分叉对。这也符合用户的约束,但请 GPT 帮忙确认是否认可。
4. **评测也应改用分叉点。** 分叉点的标签由反事实决定,原则上不受步长影响,这一点需要先实测。目前的试点只有 79 个点、12 次翻转,统计检验力不够。上一轮的两条事后线索(TEgc 上 OAT 控制后约 0.59;NLL_base − NLL_tapt 控制后 0.58 / 0.60)应带着步长控制写成预注册 v2,在扩大后的分叉数据上检验。
