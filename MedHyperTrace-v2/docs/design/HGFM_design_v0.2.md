# MedHyperTrace-v2 设计 v0.2：把超图基础模型文献落实到架构（第 35 轮，2026-10-21）

**起因：** 用户指出，v0 编码器没有体现已读过的超图基础模型文献（IHP、HYPER、Beyond Graphs、HypeBoy、HyperG），也没有体现基于图的 MAS 故障归因文献。核对后这个批评成立：`hgfm/model_v0.py` 本质上是按关系类型分参数的均值消息传递（HGNN+ / R-GCN），任务向量只是拼接上去。它和 v1 同源，**不包含任何超图基础模型特有的机制**。
**处理：** v0 降级为**结构基线**（名称 `HGNN-baseline`），仍然跑完第一阶段，作为"普通超图网络"和"无结构"两条对照。v2 的方法本体按本文重新设计为 **HGFM v0.2**。

编号 #N 对应 `docs/lit/graph_llm_118/`，MAS 文献对应文献仓库 `chancanmakeit/graph-based-mas-fault-attribution-papers`。

## 1. 文献 → 组件对照表

| 组件 | 来自哪篇 | 原文机制 | 在 MAS 轨迹上怎么改 | 解决什么问题 |
|---|---|---|---|---|
| **C1 位置感知的 k 元超边消息** | **HYPER（#54）** | 知识超图上 k 元超边的位置（参数槽）用 sinusoidal 编码加 MLP 得到 x_{a,b}；消息为 ⊙_{j≠i}(α·h_j + (1−α)·p_j) ⊙ x_{a,b} | 位置 = 成员在超边里的**角色槽**。read 超边：head（写入者）为 0，tail 按 `how` 分槽（verbatim / excerpt / structured_field / protocol）。control 超边：选择者、被选者。event 超边成员无序，统一用一个"成员"槽，保持置换不变 | 区分"读了谁的原文"和"只读了票数"；一次调用读多个前序步，真正当 k 元关系处理 |
| **C2 关系图，跨框架零样本的核心** | **HYPER（#54）**、ULTRA（#3） | 关系类型作节点；r1 第 i 位与 r2 第 j 位共享实体时连一条 (i, j) 边；在关系图上做查询条件化的消息传递得到关系表示，对关系改名不变；3 个 KG + 2 个超图预训练即超过在 50 个 KG 上训练的 ULTRA | 关系类型 = (超边类型 × 角色槽 × 头步骤的阶段)。不同框架的阶段名、角色名互不相同，但"关系之间如何共享步骤"的结构可以迁移，关系图对改名不变 | 新框架的阶段 / 角色词表没见过时，零样本仍然能用 |
| **C3 超边文本指令** | **IHP（#53）**、REEF（#50） | PHC 层：超边表示 = 成员均值 + γ·p_e，p_e = 冻结 MiniLM(超边的文本指令) 再过一层线性变换；微调时冻结提示变换、只调目标侧，λ_t 自适应强度。REEF 用关系文本经超网络生成参数 | 每条超边自动生成一句指令，例如"第 1 轮复核中，内科医生读取了综述报告和三份初始意见"，由 schema 字段模板化生成，再拼接 `framework_description`。C2 中关系节点的初值也用关系文本的嵌入（语义初始化，REEF 消融显示它最关键） | 框架的语义靠文本承载，换框架只需换描述；对新框架的轻量 adapter = 只调指令变换和 γ |
| **C4 查询感知的 edge→node 传播** | **HyperG（#93）**、GFM-RAG（#108） | PHL：node→edge 用多头超图注意力；edge→node 以 prompt 中的任务询问为 query 与超边交互。去掉询问嵌入掉 5.76%；用经典 HGNN 替换 PHL 掉 4.50% | query = [题目嵌入；系统最终答案；（审计设定下）金标准]；edge→node 注意力只把与"这次失败"相关的超边信息传回步骤节点。替换 v0 的"拼接任务向量" | 归因是查询条件化的问题（"谁对这个错误答案负责"），不同于通用的节点表示 |
| **C5 生成式超图自监督** | **HypeBoy（#52）** | 超边填充：给定超边去掉一个成员后的子集，预测缺失成员（余弦相似 softmax，Deep Sets 求和加投影头）；先做 GraphMAE 式掩码特征重构热身；有热身平均排名 1.4，无热身 3.3 | ① 热身：掩码步骤输出嵌入并重构；② read 超边填充：给定 head 和部分 tail，预测缺失的来源步，候选为同一轨迹内的全部前序步；③ 填充损失作为零样本**异常分数**（偏离群体的成员难以被预测，需实验验证）。语料用 MedAgentAudit 14k 条加 medical-aegis 的 normal 运行，不需要标签 | 不依赖注入标签，绕开注入签名；人工标注稀缺时先学轨迹结构 |
| **C6 超边软 token 进冻结 LLM** | **HyperG（#93）**、TEA-GLM（#98）、GraphGPT（#55）、G-Retriever（#58）、G-reasoner（#85） | HyperG：超边嵌入经两层 projector 变成 prompt 占位 token，LoRA（r=8，只动 QKV），约增加 189M 参数，8B 模型可比 70B 序列化方法。TEA-GLM：GNN 表示与 LLM token 空间做特征级对齐，用于零样本。G-Retriever：图 token 与文本化互补（去掉任一侧分别掉 22.5% 和 19.2%）。G-reasoner：GNN 打分加 LLM 读 top-k | 编码器先给全部步骤和超边打分，top-k 候选步骤和超边各变成一个软 token，同时附上这些步骤的原文节选；冻结 LLM（Qwen3-8B）生成"(agent, step, 故障码, 理由)" | 超图负责结构定位，LLM 负责内容判断。故障往往在内容层面，纯结构方法判断不了"这条医学判断错了" |
| **C7 约束解码** | PromptGFM（#51）、RAR（#71） | 前缀树限定合法输出；无约束时，答案正确的情况下仍有 44% 的路径幻觉 | 只允许输出轨迹中真实存在的 (agent_id, step_id) 和体系内的故障码 | 杜绝归因到不存在的步骤 |
| **C8 文本化超图基线与能力边界** | **Beyond Graphs / LLM4Hypergraph（#92）** | 7 种超图描述语言：高阶语言（HO-Inc、N-Set 等）在高阶任务上占优，低阶语言在中高难度低阶任务上更好；同构识别约 50%；超图越大越差；Hyper-COT v3 平均约 +4% | ① 强基线："把轨迹超图用 HO-Inc / N-Set 写成文本 + Hyper-COT v3"直接问 LLM，不训练；② 低阶写法（N-Pair）对照，检验超边对 LLM 读者是否必要；③ 设计依据：LLM 读文本化超图在结构上能力有限、且随规模退化，这是 C6 选择"编码后再注入"而不是"写成文本"的理由 | 回答"为什么不直接让 LLM 读超图文本" |

## 2. 基于图的 MAS 故障归因文献：吸收什么、怎样对比

| 文献 | 用在哪里 |
|---|---|
| **GraphTracer**（IDG）、**AgentTrace**（数据依赖边）、**CHIEF**（分层因果图）、**DCFA**（经 LLM 判定后才加入的依赖边）、**EMFA**（信息依赖图 / 错误传播图 / 循环图） | read 超边的来源：这些都是二元依赖边，v2 推广为 k 元有向超边，并要求在生成时记录（medical-aegis 的 `sources`）。EMFA 的"持续循环图"对应辩论类的重复（MedAgentAudit 2.2.1） |
| **GRADE** | 边的证据等级（`how`）；必做"度数匹配的伪造依赖层"对照 |
| **AFANet** | 最接近的竞品：轮次图加 GCN。它的消融显示结构增益小（域内去掉全部边 74.16→71.26，OOD 37.93→32.18）。这是 v2 必须超过的结构基线 |
| **SOAP**（无步骤标签的归因：软依赖图上误差证据回流） | C9：**只用结果标签的责任分配**。用结果头（是否答错）加图上的反事实掩码（COSMOS #38 的 ΔScore：去掉某步或某超边后，失败概率下降多少）给出步骤责任分，不需要步骤标签 |
| **Node Contribution Backpropagation**（有符号 DAG 上反传贡献度） | C9 的对照方法，也是可解释性的参照 |
| **AgentTether**（在正常遥测上自监督训练异构图 Transformer）、**BlindGuard**（只用正常行为、对比学习检测未知攻击） | 支持 C5 只用 normal 运行做预训练、再做异常打分的路线；作为"无监督"基线 |
| **G-Safeguard**（GNN 节点异常分数）、**XG-Guard**（句子级加 token 级双层分数，可解释） | 节点级异常分数作为 agent 定位基线；XG-Guard 的双层分数对应步骤级和片段级的细粒度解释 |
| **EDGE**（故障类别之间的传播图，Suppes 加 CAPRI 加反事实验证） | 故障码之间的传播先验：在输出头加码间依赖（例如 2.1.2 知识激活不足 → 3.1.1 少数意见被压制） |
| **CausalFlow**、**Causal Agent Replay** | 用反事实重放**验证**责任标签：请 medical-aegis 对 `flipped` 样本把被注入步换回干净输出后重跑，确认结果翻回 |
| **Adaptive Influence Graphs**、**FALAT**、**STRACE**、**CDC-MAS** | 免训练对照（LLM 建图 + LLM 读图 / 依赖回溯 / 因果发现加 Shapley） |
| **HPFA**（成对超图归因，COLM 2026） | 成对运行分歧伪标签；它也是"超图 + 归因"的先例（单智能体），限定了 v2 的新颖性表述 |
| **HyperAgent**（用超图优化 MAS 通信拓扑）、**MAGE**（时序超图记忆） | "超图建模 MAS"的先例，用于拓扑优化和记忆，不做归因。必须引用，说明 v2 不是"首个把超图用于 MAS" |
| **MedAgentAudit** | 故障体系、自然失败数据和审计员；第一阶段的训练与评测来源 |

## 3. HGFM v0.2 前向流程

1. **建图**（已实现，`uth.py`）：节点、有向超边；为每个成员加角色槽（C1）；为每条超边生成文本指令（C3）。
2. **关系编码**（C2）：在本轨迹的关系图上，以 query 为条件做 2 层消息传递，关系节点初值 = 关系文本嵌入，得到每种关系的表示 r。
3. **实体编码**（C1 + C3 + C4）：L 层。node→edge：位置感知的多头注意力，超边表示 = 成员聚合 + γ·指令嵌入，再乘以关系表示 r 做调制。edge→node：以 query 为 key 的注意力把信息传回节点；read 超边正反两向都传。
4. **输出头**：步骤 × 故障码（多标签，含码间依赖，见 EDGE）；运行级结果；C9 用反事实掩码得到步骤责任分。
5. **LLM 层**（C6 + C7）：top-k 步骤和超边的软 token，加上原文节选，送入冻结 LLM，约束解码。
6. **训练顺序**：C5 自监督（无标签，全部轨迹）→ 缺陷层弱监督（审计员标签）与结果监督 → 责任层（注入的 `flipped`）→ LLM 投影器加 LoRA（只训投影器和 QKV）。新框架只调 C3 的指令变换和 γ（IHP 式 adapter）。

## 4. 必做的对照与消融（论文用）

- 结构：HGNN-baseline（即 v0）、无结构（L0）、星形展开（ULTRA 式 reified）对比超边、度数匹配伪造（GRADE）、打乱边（#43）。
- 逐个组件：去掉 C1 位置、C2 关系图（换成固定关系参数）、C3 指令（γ=0 即退化为 PHC）、C4（改为拼接 query）、C5 预训练、C6 LLM 层。
- LLM 读者：文本化高阶超图（HO-Inc / N-Set）+ Hyper-COT v3，文本化低阶图（N-Pair），同一骨干的轨迹文本 LoRA。
- MAS 归因：AFANet、CHIEF / Adaptive Influence Graphs、GraphTracer、SOAP、Node Contribution Backprop、G-Safeguard、BlindGuard。
- 评测：留一家族零样本、锚点任务、MedAgentAudit 400 例人工标注、MAFA。

## 5. 实施顺序

1. 第一阶段 v0 跑完，作为 HGNN-baseline 与无结构对照（正在进行，不改）。
2. 实现 C1–C4（编码器本体），先在 MedAgentAudit 上与 v0 对照：在同样数据上，位置、关系图、指令、查询注意力是否有增益。
3. C5 自监督预训练。
4. C9 只用结果标签的责任分配。
5. C6 / C7 的 LLM 层需要 GPU，在用户的 4×A6000 上做；在沙箱里先准备好数据和代码。
