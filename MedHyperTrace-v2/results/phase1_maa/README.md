# 第一阶段结果：MedAgentAudit（2026-10-21，第 33–37 轮）

**数据：** MedAgentAudit 14,370 条轨迹，排除 mdagents 的 basic 和与锚点重复的题之后剩 12,409 条。弱监督用 LLM 审计员的标签，评测真值用 400 例人工标注（3 票取多数）。**只在 MedAgentAudit 体系内**。
**划分：**
- **LQD**：留一 MAS 且题目不重叠（`hgfm/splits_maa.py`），这是跨框架零样本的主结果。
- **QD**：MAS 都见过、题目不重叠。
- 原 LOMO 划分（`v0_leaky_lomo_log.txt`）存在题目泄漏，**作废**：其中结果预测 AUROC 为 0.82–0.90，同一模型在题目不重叠时只有 0.62。

**模型：**
- L0：无结构，特征与其他组完全相同。
- v0：HGNN 基线，即按关系类型的均值消息传递。
- v0.2：C1–C4，即 HYPER 式位置编码、关系图、IHP 式超边指令、HyperG 式查询注意力；no_* 为去掉单个组件的消融。
- +gold：节点特征加入"答案是否等于金标准"，对应审计设定。

## 结论

1. **跨框架零样本时，在人工标注上没有看到结构带来的显著增益。** 普通超图基线（v0）和 v0.2（C1–C4）相对无结构都在误差范围内；单个组件的贡献也都不显著，点估计最大的是查询注意力（+0.021）和超边指令（+0.018）。
2. **结构在弱标签上有稳定增益**（0.654 → 0.691 → 0.700；去掉查询注意力降到 0.674）。这一项样本量大，但它是在学习复现审计员。人工标注上看不到同样的增益，可能有两种原因：一是每个故障码只有约 40 例，检测力不够；二是学到的结构信号是审计员特有的。
3. **交互类故障才是结构理应起作用的地方，但所有变体都只有 0.56–0.62。** 这类故障的判据需要知道"谁对谁错"：例如"少数意见被压制"要求少数派正确、而多数派错误。MiniLM 的节点嵌入做不了医学内容判断，结构只能传递"谁和谁意见一致"这样的信号。这与设计 v0.2 中 C6（LLM 层负责内容判断）的动机一致，但目前还没有实证。
4. 给金标准时 v0.2 相对 v0 有显著提升（+0.040），说明一旦节点上有"对或错"的信息，v0.2 的结构组件能把它传到交互类故障上。这是目前唯一支持结构组件的证据。
5. **离审计员还很远**（0.69 对 0.89）。审计员是大模型读全文、并且看了金标准，评测集又按它的判定分层抽样；小编码器加 MiniLM 嵌入不可能接近这个水平。

## 对下一步的含义
- 不能宣称"超图结构提升了零样本归因"。要证明结构有用，需要：(a) 节点表示具备内容判断能力，即 C6 LLM 层，或换成更强的医学文本编码器；(b) 更大的人工评测集；(c) 在责任层（锚点注入数据的 flipped）上评测，那里的传播链比缺陷层更依赖结构。
- C5 自监督和 C9 只用结果标签的责任分配可以在 CPU 上继续做；C6 需要 GPU。
